## 一、为什么 VLA 一定要补机器人基础

在 `01-VLA算法入门` 里，我们主要关注：

- 视觉编码器怎么选
- 语言模型怎么接
- action head 用离散、diffusion 还是 flow
- 训练数据和微调范式怎么设计

但一旦进入真机，问题会立刻变成下面这些：

- 模型输出的 `Δx, Δy, Δz` 是在**相机坐标系**里，还是**机器人基坐标系**里？
- 姿态该用欧拉角、旋转矩阵，还是四元数？
- 输出的是**末端位姿增量**，还是**关节角增量**？
- 这个动作命令是直接发给电机，还是先走 IK、再给控制器？
- 控制频率是 5 Hz、20 Hz 还是 100 Hz？策略频率和底层控制频率不一致怎么办？
- 为什么离线回放轨迹没问题，真机一动就抖、偏、撞？

所以，VLA 真正落地时，常见失败往往不是「模型理解不了指令」，而是：

1. **坐标系没对齐**
2. **动作空间定义不合理**
3. **控制器接口不匹配**
4. **观测延迟或标定有误**
5. **策略频率和机器人闭环频率断层**

一句话说，**VLA 决定“想怎么动”，机器人学决定“能不能这么动、怎么才能稳地动”。**

## 二、机器人系统的最小闭环

把一个 VLA 机器人系统压缩到最核心，可以看成下面这个闭环：

```text
相机 / 深度 / 关节状态 / 力传感器
                ↓
         状态估计与预处理
                ↓
      VLA / Policy 输出高层动作
                ↓
      动作后处理（裁剪、平滑、插值）
                ↓
    IK / 轨迹生成 / 控制器接口适配
                ↓
     底层控制器（PID / 阻抗 / 力控）
                ↓
        电机 / 机械结构 / 环境交互
                ↓
             新观测返回
```

这里最容易被忽略的点是：**策略输出并不等于执行命令。**

例如，VLA 输出：

```python
action = [0.01, -0.02, 0.03, 0.0, 0.0, 0.1, 1.0]
```

这 7 维动作通常只表示「末端执行器下一小步该往哪动、夹爪该开还是关」，它往往还要经过：

- 坐标系转换
- 尺度缩放
- 安全裁剪
- 逆运动学
- 平滑滤波
- 底层控制器

最后才真正变成关节电机能执行的命令。

这也是为什么在项目里，你经常会看到：

```text
policy frequency = 10 Hz
control frequency = 100 Hz
```

高层策略慢一些，底层控制快一些，中间靠 action chunk、插值或局部控制来补齐。

## 三、坐标系：你到底在谁的参考系里说话

### 3.1 机器人里最常见的几种坐标系

如果不先把坐标系讲清楚，后面所有动作定义都会混乱。

最常见的坐标系有：

- **世界坐标系（world frame）**：场景的全局参考系
- **机器人基座坐标系（base frame）**：机械臂底座固定的参考系
- **末端执行器坐标系（end-effector / tool frame）**：夹爪或工具头自己的参考系
- **相机坐标系（camera frame）**：以相机光心为原点
- **物体坐标系（object frame）**：某个杯子、盒子、零件的局部参考系

一个典型例子：

```text
桌上有个杯子
相机看到杯子在自己右前方
但对机械臂基座而言，杯子可能在左前方
如果直接把 camera frame 下的位置当成 base frame 去执行，动作一定错
```

所以只要视觉进来了，几乎一定会涉及变换链：

```text
object in camera frame
    ↓
camera -> base 外参变换
    ↓
object in base frame
    ↓
生成 end-effector 目标位姿
```

### 3.2 变换的本质

机器人里常把从坐标系 `B` 到坐标系 `A` 的刚体变换写成：

```text
T_A_B
```

意思是：把 `B` 坐标系中的点，变换到 `A` 坐标系中。

齐次变换矩阵形式：

```text
T = [ R  t ]
    [ 0  1 ]
```

其中：

- `R` 是 `3x3` 旋转矩阵
- `t` 是 `3x1` 平移向量

一个点 `p_B` 转到 `A` 系：

```text
p_A = T_A_B * p_B
```

### 3.3 为什么这对 VLA 特别重要

因为很多 VLA 的动作定义默认是：

- 在 **base frame** 下输出末端增量
- 或在 **tool frame** 下输出局部相对动作

这两者效果会非常不一样。

例子：

```text
动作 1：沿 base-x 正方向移动 2 cm
动作 2：沿 tool-x 正方向移动 2 cm
```

如果夹爪当前已经旋转了 90 度，那么这两个动作在真实空间里的方向并不一样。

因此在项目中必须明确：

1. 模型输出在哪个参考系下定义
2. 控制器接收哪个参考系下的命令
3. 中间是否做了变换

这是最基础也最容易出错的一层。

## 四、位姿表示：位置 + 朝向怎么表达

一个刚体的位姿（pose） = **位置（position）+ 朝向（orientation）**。

### 4.1 位置表示

位置最简单，就是三维向量：

```python
position = [x, y, z]
```

通常单位是米。

### 4.2 姿态表示的四种常见方式

#### 方式 1：欧拉角（roll, pitch, yaw）

```python
orientation = [roll, pitch, yaw]
```

优点：

- 直观
- 人类好理解

缺点：

- 有万向节锁问题
- 插值不稳定
- 不同旋转顺序含义不同

#### 方式 2：旋转矩阵

```python
R.shape == (3, 3)
```

优点：

- 数学表达完整
- 坐标变换直接好用

缺点：

- 9 个数冗余
- 训练回归时约束难处理

#### 方式 3：四元数

```python
q = [qx, qy, qz, qw]
```

优点：

- 无万向节锁
- 插值平滑
- 机器人控制与 SLAM 中很常用

缺点：

- 不直观
- 需要单位化
- `q` 和 `-q` 表示同一旋转，训练时要注意符号等价

#### 方式 4：6D rotation representation

深度学习里常见一种做法：用 6D 表示旋转，再通过正交化恢复旋转矩阵。

优点：

- 比欧拉角更连续
- 比直接回归旋转矩阵更适合学习

缺点：

- 工程部署时最终还是要转成四元数或旋转矩阵

### 4.3 工程上怎么选

粗略建议：

| 场景 | 常用表示 |
|------|----------|
| 人工调试 / 可视化 | 欧拉角 |
| 控制与变换 | 旋转矩阵 / 四元数 |
| 深度学习训练 | 四元数 / 6D rotation |

### 4.4 为什么 VLA 常输出增量姿态

很多机器人策略不直接输出绝对位姿：

```python
target_pose = [x, y, z, roll, pitch, yaw]
```

而是输出增量：

```python
delta_pose = [dx, dy, dz, droll, dpitch, dyaw]
```

原因是：

1. 增量动作更平滑
2. 更容易适配不同初始状态
3. 更适合闭环控制
4. 更符合遥操作数据采集习惯

所以 VLA 文献里常见的 7 维动作：

```text
[Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper]
```

本质上就是一种**末端相对增量控制**。

## 五、运动学基础：正解、逆解、雅可比

### 5.1 正运动学 FK

正运动学（Forward Kinematics, FK）回答的问题是：

> 已知每个关节角，末端执行器现在在哪？

记关节角为：

```python
q = [q1, q2, ..., qn]
```

那么：

```text
end_effector_pose = FK(q)
```

这一步是确定性的几何计算。

### 5.2 逆运动学 IK

逆运动学（Inverse Kinematics, IK）回答的问题是：

> 如果我想让末端到达某个位姿，关节该怎么转？

即：

```text
q* = IK(target_pose)
```

这对 VLA 非常关键，因为很多策略输出的是**末端动作**，但机器人执行的却是**关节命令**。

中间往往要走：

```text
VLA 输出末端增量
    ↓
生成目标末端位姿
    ↓
IK 求目标关节角
    ↓
底层控制器执行
```

### 5.3 为什么 IK 不总是好解

IK 常见难点：

- 可能有多个解
- 也可能无解
- 靠近奇异位形时会很不稳定
- 解可能超出关节限位
- 解虽然数学上可行，但轨迹不自然、容易碰撞

所以实际工程里常加额外约束：

- 离当前关节配置最近
- 避开关节极限
- 避开自碰撞
- 保持手腕姿态稳定

### 5.4 雅可比矩阵的直觉

雅可比矩阵 `J(q)` 描述的是：

> 关节速度如何映射成末端线速度与角速度

```text
x_dot = J(q) * q_dot
```

这里：

- `q_dot` 是关节速度
- `x_dot` 是末端 twist（线速度 + 角速度）

它有两个非常重要的用途：

1. **速度控制 / 微分 IK**
2. **力与扭矩映射**

很多基于增量位姿的控制，本质上就是用雅可比做局部线性近似，把末端速度需求转成关节速度命令。

### 5.5 什么是奇异位形

当机械臂到达某些特殊姿态时，雅可比会退化，导致：

- 某些方向几乎动不了
- 很小的末端动作要求很大的关节速度
- 控制抖动、爆速、数值不稳定

这就是常说的奇异位形（singularity）。

在 VLA 项目里，如果你发现：

- 某些姿态下动作突然发散
- 轨迹本来顺，但接近某个姿态时手抖得很厉害

那就不能只怀疑模型，也要怀疑是不是 IK 或雅可比条件数出了问题。

## 六、动作空间设计：VLA 到底应该输出什么

这是连接模型与机器人执行的关键接口。

### 6.1 三种最常见的动作空间

#### 方案 1：关节空间动作

```python
action = [q1, q2, ..., qn, gripper]
# 或
action = [dq1, dq2, ..., dqn, gripper]
```

优点：

- 直接对应执行器
- 不需要额外 IK

缺点：

- 与机器人本体强绑定
- 跨机器人泛化差
- 语义不直观

#### 方案 2：末端执行器空间动作

```python
action = [dx, dy, dz, droll, dpitch, dyaw, gripper]
```

优点：

- 语义直观
- 更接近人类示教
- 便于跨机械臂迁移

缺点：

- 需要 IK 或笛卡尔控制器
- 接近奇异位形时可能不稳

#### 方案 3：统一动作空间

这类做法常见于多机器人基础模型，如 RDT 路线：

- 用通用物理语义定义动作
- 不同机器人映射到同一超空间

优点：

- 利于跨本体训练
- 更适合 foundation model

缺点：

- 工程适配复杂
- 需要高质量的动作规范化与掩码机制

### 6.2 为什么很多项目喜欢末端增量

因为它在工程上是一个很好的折中：

- 比关节空间更语义化
- 比绝对位姿更稳
- 比高层离散技能更细粒度

典型形式：

```python
action = [dx, dy, dz, d_rx, d_ry, d_rz, open_close]
```

其中平移与旋转通常还会做裁剪：

```python
dx, dy, dz = clip(action[:3], -0.02, 0.02)
d_rx, d_ry, d_rz = clip(action[3:6], -0.1, 0.1)
```

这一步很重要，因为模型偶尔输出异常值时，裁剪能直接救命。

### 6.3 单步、chunk 与轨迹级输出

动作不仅要定义“是什么空间”，还要定义“时间上输出多长”。

#### 单步动作

```python
action_t = policy(obs_t)
```

优点：简单、闭环强。  
缺点：对推理频率要求高。

#### Action chunk

```python
actions = policy(obs_t)   # shape: [H, action_dim]
```

优点：

- 缓解模型推理慢的问题
- 轨迹更平滑
- 适合 diffusion / flow policy

缺点：

- 开环执行比例变高
- 中间如果环境变了，后续动作可能过时

#### 轨迹级 / 子目标级输出

更高层的 policy 不直接发每一步，而是发：

- 若干关键点
- 子目标 pose
- 技能调用序列

这更像分层规划，不是本文主线，但后续学 ACoT、世界模型、层次 RL 时会经常遇到。

### 6.4 选动作空间时的经验原则

如果你是做机械臂 VLA 落地，常见经验是：

1. **先用末端增量空间起步**
2. **保持动作尺度小、频率稳定**
3. **夹爪单独建模**
4. **绝对值命令慎用**
5. **训练与部署动作定义必须完全一致**

最后这一点极其重要。很多“训练很好、部署崩了”的问题，本质上是训练时的动作归一化或参考系定义，和部署代码不一致。

## 七、控制链路：从策略输出到电机执行

### 7.1 一个典型控制栈

以机械臂抓取为例，一条常见链路是：

```text
RGB 图像 + 关节状态 + 指令
        ↓
     VLA 策略
        ↓
  输出末端 delta pose
        ↓
  坐标转换 / 安全裁剪
        ↓
   IK 或笛卡尔伺服
        ↓
  关节位置 / 速度目标
        ↓
 ros2_control / 厂商控制器
        ↓
       电机执行
```

这里可以把控制分成三层来理解。

### 7.2 高层、中层、底层

#### 高层策略层

通常是 VLA / RL policy，负责：

- 看图像、读指令
- 理解任务目标
- 给出高层动作建议

输出频率通常不高，例如：

- 5 Hz
- 10 Hz
- 20 Hz

#### 中层运动接口层

负责把策略输出变成可执行命令：

- 末端增量积分成目标位姿
- 做 IK
- 轨迹插值
- 检查关节限位
- 做动作平滑

这一层常常决定系统是否稳定。

#### 底层伺服层

负责真正闭环跟踪：

- PID
- 位置环 / 速度环 / 电流环
- 阻抗控制
- 力矩控制

这层运行频率通常比策略高一个量级，常见是：

- 100 Hz
- 250 Hz
- 500 Hz
- 1 kHz

### 7.3 为什么策略不能直接替代控制器

因为策略再强，也通常不负责处理这些问题：

- 电机延迟
- 摩擦与背隙
- 柔顺接触
- 机械振动
- 执行误差闭环修正

所以多数 VLA 系统的正确理解不是：

```text
VLA 直接控制机器人一切
```

而是：

```text
VLA 决定“往哪去、怎么做”
控制器保证“尽量稳地做到”
```

## 八、常见控制方式：位置、速度、力与阻抗

### 8.1 位置控制

最常见，也最容易上手。

策略给出目标关节角或目标末端位姿，控制器负责跟踪。

优点：

- 简单
- 稳定
- 工业机械臂支持最好

缺点：

- 对接触任务不够柔顺
- 碰到环境时容易“顶死”

### 8.2 速度控制

策略输出目标速度：

```python
q_dot_cmd
# 或
twist_cmd
```

优点：

- 平滑
- 适合连续微调

缺点：

- 需要更稳定的高频闭环
- 噪声或延迟会更明显

### 8.3 力控制

当任务需要控制接触力时，比如：

- 擦桌子
- 插拔
- 拧盖子
- 装配

就不能只关心“到哪”，还要关心“压多大力”。

这时会引入：

- 力传感器
- wrench 反馈
- 力闭环

### 8.4 阻抗控制

阻抗控制可以直观理解成：

> 不只规定位置，还规定“像弹簧阻尼系统一样”的柔顺响应

它非常适合接触任务，因为它允许机器人：

- 贴着环境轻柔移动
- 遇到小扰动时自动让步
- 减少刚性碰撞

对具身智能来说，阻抗控制是一个很值得理解的概念，因为很多“策略看上去没错，但真机接触一塌糊涂”的任务，最后要靠阻抗或混合力位控制来兜底。

### 8.5 面向 VLA 的粗略建议

| 任务类型 | 更常见的底层控制 |
|----------|------------------|
| 抓取、搬运、放置 | 位置控制 / 笛卡尔伺服 |
| 高频跟随、平滑移动 | 速度控制 |
| 接触、插拔、擦拭 | 阻抗控制 / 力控 |
| 灵巧手精细操作 | 力控 + 高频局部策略 |

## 九、观测、本体感知与标定

VLA 不只是吃图像。只靠图像，往往不够稳。

### 9.1 本体感知（proprioception）是什么

本体感知通常包括：

- 关节角 `q`
- 关节速度 `q_dot`
- 末端位姿
- 夹爪状态
- 力 / 扭矩
- 历史动作

这些信息的价值在于：它告诉策略“我现在身体在哪、刚才干了什么”。

对于闭环控制，这些信息常常和视觉同等重要。

### 9.2 为什么很多任务需要历史信息

单帧视觉常常不够，因为：

- 物体会被手挡住
- 接触状态无法仅靠静态图像判断
- 速度与趋势需要时间信息

所以常见做法有：

- 堆叠最近 `k` 帧观测
- 输入最近 `k` 步动作
- 输入机器人状态历史
- 用 transformer / RNN 建模时间上下文

### 9.3 标定：从“看到了”到“够得着”

标定是视觉机器人系统里最基础的真值桥梁。

最常见有三类：

#### 相机内参标定

得到：

- 焦距
- 主点
- 畸变参数

用于把像素信息和空间几何联系起来。

#### 相机外参标定

得到相机与机器人基座、世界坐标之间的变换：

```text
T_base_camera
```

如果外参不准，就会出现：

- 识别位置看起来对
- 实际抓取总偏几厘米

#### 手眼标定

当相机装在手上（eye-in-hand）时，需要知道：

```text
T_ee_camera
```

这对视觉伺服和抓取定位非常关键。

### 9.4 时间同步

很多初学者只盯空间标定，忽略时间同步。

但如果：

- 图像时间戳滞后 100 ms
- 关节状态是上一拍的
- 策略输出动作对应的不是当前观测

那么整个系统就相当于一直在“看旧世界、控新身体”，结果往往是：

- 跟踪滞后
- 抓取偏移
- 动作振荡

所以部署时要特别关注：

- 传感器时间戳
- 推理耗时
- 控制回路周期
- 命令下发延迟

## 十、部署中的常见问题：为什么模型看起来对，机器人却做不好

这一节最贴近真实项目。

### 10.1 坐标系错误

最典型的问题之一：

- 模型输出的位移方向“看起来合理”
- 但机器人总往斜方向走

常见原因：

- camera frame 和 base frame 混用
- 左手系右手系搞反
- 姿态旋转顺序不一致

### 10.2 动作尺度不对

训练时动作归一化到 `[-1, 1]`，部署时如果反归一化错了，就会出现：

- 过小：机器人像不敢动
- 过大：一步冲飞

所以动作空间不仅要定义维度，还要定义：

- 单位
- 范围
- 裁剪规则
- 是否是 delta
- 是否在某坐标系下

### 10.3 控制频率不匹配

例如：

- 策略 5 Hz
- 控制器 200 Hz

如果没有 chunk、插值或保持策略，机器人就会：

- 一顿一顿地走
- 轨迹不连续
- 接触任务不稳

### 10.4 训练部署分布不一致

训练时：

- 视角固定
- 光照稳定
- 物体位置分布窄
- 机器人状态初始化理想

部署时：

- 光照变了
- 相机轻微偏了
- 台面反光
- 夹爪初始张开程度不同

这会直接导致 policy 崩掉。

### 10.5 接触任务只用位置控制

例如插孔、扣合、沿表面滑动等任务，如果底层仍是很硬的位置控制，常见现象是：

- 轨迹看上去对
- 一接触就卡住或弹开

这时问题可能不在 VLA，而在底层控制策略不适合接触。

### 10.6 没有安全层

真实机器人必须有安全层兜底，例如：

- 关节限位
- 速度上限
- 工作空间边界
- 自碰撞检测
- 紧急停止
- 夹爪力限制

很多项目里，安全层不是“锦上添花”，而是 policy 能不能上真机的前提。

## 十一、面试与项目里最常被追问的点

如果你在面试里讲 VLA 项目，下面这些问题非常高频。

### 11.1 为什么很多 VLA 输出末端增量，而不是直接输出关节角

一个比较完整的回答可以是：

- 末端空间更符合任务语义
- 更接近人类遥操作数据
- 更利于跨机械臂迁移
- 增量式闭环更稳定
- 关节空间虽然直接，但本体耦合太强

然后补一句限制：

- 末端空间通常仍需 IK 或笛卡尔控制器支持

### 11.2 为什么真实机器人里还需要底层控制器，不能纯端到端

可以这样回答：

- 高层策略解决任务理解和动作决策
- 底层控制器解决高频闭环、执行误差、接触稳定性
- 两者频率和职责不同，不能简单互相替代

### 11.3 为什么相同模型换个相机位姿就掉点很多

可以从三层解释：

1. 感知分布变化
2. 相机外参变化导致几何映射偏移
3. 训练数据对新视角覆盖不足

### 11.4 为什么 RL 在真机上比仿真难得多

因为真机面对的不是纯优化问题，而是：

- 安全约束
- 样本成本
- 延迟
- 传感器噪声
- 接触不确定性
- 奖励难定义

所以机器人 RL 经常采用：

- IL 初始化
- 仿真预训练
- 少量真机微调
- 安全约束或人类监督

### 11.5 如何判断问题在模型、控制器还是标定

一个常用排查思路：

1. **离线回放策略输出**：看动作逻辑是否合理
2. **固定观测单步执行**：看动作方向和尺度是否对
3. **绕过策略直接给人工 pose**：验证 IK 和控制器
4. **检查相机外参与时间戳**：验证标定与同步
5. **看接触瞬间表现**：判断是否需要阻抗/力控

这个回答会非常工程化，也很像真的做过项目的人。

## 十二、学习路径建议

如果你是从 VLA 继续往下学机器人基础，我建议按下面顺序走。

### 阶段 1：先补几何与位姿直觉

目标：能真正看懂坐标变换和姿态表示。

建议掌握：

- 坐标系定义
- 齐次变换矩阵
- 欧拉角、四元数、旋转矩阵
- base / camera / tool frame 的区别

学习完成标志：

- 你能解释一条抓取点是如何从图像坐标一步步变到机器人基坐标系的

### 阶段 2：补运动学与控制接口

目标：搞清策略输出如何落到机器人执行层。

建议掌握：

- FK / IK
- 雅可比矩阵
- 关节空间与末端空间控制
- 位置 / 速度 / 阻抗控制

学习完成标志：

- 你能清楚解释 `Δpose -> IK -> controller -> motor` 这条链路

### 阶段 3：补标定、同步与部署

目标：理解真机系统为什么会“看着对但做不对”。

建议掌握：

- 相机内外参
- 手眼标定
- 时间同步
- 控制频率设计
- 安全层与工作空间约束

学习完成标志：

- 你能独立列出真机部署前的检查清单

### 阶段 4：再回看 VLA 与 RL

到这一步，再回去看：

- 为什么很多 VLA 选末端增量
- 为什么 action chunk 能缓解推理延迟
- 为什么 RL 后训练常只更新 action head
- 为什么接触任务常需要更强的本体感知和底层控制

你会发现很多之前看起来只是“论文设计选择”的东西，背后其实都有明确的机器人学原因。

## 一页速记

最后把本文压缩成一页：

1. **VLA 输出不是最终电机命令**，中间还有坐标变换、IK、控制器和安全层。
2. **坐标系必须讲清楚**，尤其是 `camera frame`、`base frame`、`tool frame`。
3. **位姿表示要分清位置和姿态**，工程上常用四元数或旋转矩阵，学习里常见增量欧拉角。
4. **末端增量动作是常见折中**，语义好、可迁移、闭环稳，但依赖 IK 或笛卡尔控制。
5. **高层策略与底层控制器职责不同**，VLA 管决策，控制器管稳定执行。
6. **真机问题很多不是模型问题**，而是标定、同步、频率、尺度和接触控制问题。
