## 一、项目概览



### 1.1 任务定义

**目标**：双臂协同 + 双手精细配合，完成「方形纸 → 对折 → 压平折痕 → 再对折成四分之一」的基础折纸序列。

**难点**：


| 维度     | 具体挑战                   |
| ------ | ---------------------- |
| 双臂协调   | 一手持纸、一手压折痕，时序严格，不能互相碰撞 |
| L6 灵巧手 | 6 主动 DOF，指尖力分布影响纸张是否滑动 |
| 接触物理   | 纸是柔性体，仿真与真机 gap 大      |
| 数据规模   | 仅 3 小时遥操作，纯 IL 上限明显    |




### 1.2 整体技术路线

```
遥操作采集 3h demo
        ↓
π0.5 模仿学习微调（冻结 VLM + 训 Action Expert + LoRA）
        ↓
Isaac Sim 闭环评估 + Domain Randomization
        ↓
真机部署 → 暴露 sim2real gap → 针对性优化
        ↓
自主 rollout 采集（成功/失败）→ Replay Buffer
        ↓
SAC 后训练（仅更新 Action Expert，知识隔离）
        ↓
真机迭代部署
```

**为什么选 π0.5 而不是 π0 / OpenVLA**：

- **连续 Flow Matching 动作头**：折纸需要 50Hz 级精细控制，离散 token（RT-2 / OpenVLA）精度不够。
- **知识隔离（Knowledge Insulation）**：后续 SAC 梯度只打 Action Expert，不破坏 PaliGemma 的语言/视觉理解——这对「指令换步骤」的折纸子任务很关键。
- **本体状态走 VLM 文本 token**：双臂 + 双手 26 维状态离散化后进入 prefix，Action Expert 通过 KV cache 间接利用，和 openpi 官方实现一致。

**LoRA 微调简介与数学原理：**

LoRA（Low-Rank Adaptation）是一种参数高效微调方法，常用于大模型的定制。其核心思想是：不直接更新原有大模型（如 VLM 或主干网络）全部权重，而是在关键权重矩阵（如 Transformer 的全连接层、注意力层）两侧插入一组可学习的低秩分解矩阵（通常记为 $A, B$，秩 $r \ll d$），仅更新这部分参数。具体原理如下：

原本某层的权重 $W \in \mathbb{R}^{d_{out} \times d_{in}}$，微调时进行增量加法：

$$
W' = W + \Delta W = W + BA
$$

其中 $A \in \mathbb{R}^{r \times d_{in}}$，$B \in \mathbb{R}^{d_{out} \times r}$，总参数量极小。训练时只优化 $A, B$，主模型权重 $W$ 固定不变。

这样实现的好处有：

- 只需保存/更新极少的新参数（LoRA 权重），便于控制知识迁移范围与后续部署。
- 避免破坏原有模型结构与功能（如语言、视觉理解），保证“知识隔离”，下游适配性更强。
- 理论和实证都表明，这种低秩线性扰动可充分捕捉特定任务（比如动作 expert head）所需的新功能，同时不会干扰已学到的通用表征。

在本项目中，LoRA 微调仅作用于 Action Expert，意味着强化学习或模仿学习迭代时，“只操作决策层”，不会动 VLM 主干。这就能很高效地对 Action Expert 进行微调、适配，让其学会更适合当前双臂+双手折纸动作分解与控制技巧，同时保护基础的感知/指令理解能力。
当然可以！我们用自然语言再详细梳理一下 LoRA 微调的过程和原理：

1. **为什么需要 LoRA 微调？**
  传统方法如果直接微调大模型，会调整成千上万的模型参数，不仅成本高、不易移植，而且容易让模型“忘记”原来已经学会的知识。尤其在你只需要让模型**适应一个新任务（比如折纸动作决策）**时，其实完全没必要动主干网络的全部权重。
2. **LoRA 是怎么做的？**
  LoRA（Low-Rank Adaptation，低秩增量微调）采用一个巧妙的办法：**在大模型的指定层前后，插入两组很小（低秩）的矩阵参数来“拱卫”主网络**。新任务训练时，仅更新这部分小参数，其余模型全部“冻结”（不会发生变化）。
   想象一下，比如你有一台功能丰富的大机器（大模型），LoRA 好比在它关键部位安装了两个可调节的小配件，新需求来了，只用调节配件，不破坏整机，这样既快又安全。
3. **数学层面上简单解释**
  - 原本一层神经网络有个大权重 $W$，如果直接微调，需要动 $W$ 的每个元素，非常多。
  - LoRA 做法是：加上一个“小增量”，这个增量是两个小矩阵相乘 $B \times A$ 得到的（这两个矩阵秩很低，所以参数很少），实际微调时只调整 $A$ 和 $B$。
  - 主干 $W$ 完全锁死，不变。
4. **这具体有什么好处？**
  - **节省资源**：要学习的新参数极少，显存和存储压力大幅降低。
  - **保证通用能力不被破坏**：主模型保留对语言和视觉理解的整体能力。
  - **灵活定制**：针对新动作任务专门“定制”决策模块，适应性强，泛化能力不差。
  - **便于部署**：后续只需加载/切换小量 LoRA 增量参数，主模型通用，迁移方便。
5. **在本项目里怎么用 LoRA？**
  对于 π0.5 折纸项目，我们只在 Action Expert 这个“动作专家头”上用 LoRA 微调：  
  - 保证 VLM（视觉-语言主干）权重完全冻结，不影响理解能力；
  - 只让 Action Expert 学习控制“双臂+双手+纸”的新技巧；
  - 后续 RL（比如 SAC）阶段，微调和强化都只影响 Action Expert，绝不干扰对指令、图像的认知表征。

**小结一句话**：  
LoRA 微调就是用“插小配件”的办法，让大模型专注学一个新领域，不动主干，只调整少量新参数，既安全又高效——在复杂硬件控制（如折纸）尤为适合。

### 4.4 采集原则（踩坑后固化）

1. **只录成功轨迹** — 这里的「IL」指的是 VLA 的监督模仿学习（Imitation Learning, 即行为克隆）微调阶段，此阶段只用成功演示进行训练，因为失败演示会导致模型学到错误策略；至于「失败 recovery 留给 SAC 阶段」，意思是在后续强化学习（SAC, Soft Actor-Critic）阶段，允许 agent 利用失败案例和探索，在仿真或真机上通过 trial-and-error 学习「如何从中间出错状态恢复或优化」，强化学习正善于利用包括失败在内的各种经验做策略改进。
2. **纸张初始位姿 ±3 cm / ±15° 随机** — 避免过拟合固定位置。
3. **左右手分工一致** — 始终「左手持纸、右手压折」，避免标签歧义。
4. **折痕阶段放慢** — `crease` 步占时长 40%，保证 L6 指间配合有足够样本。
5. **每 30-45 min 重新标定腕部相机** —— 这样做是因为长时间采集时，机械臂和相机的空间外参（hand-eye 标定参数）会因环境温度、机械结构松动等因素逐渐漂移，导致视觉与实际动作出现偏差。如果不按时标定，后期收集的数据就不能保证精度，影响下游训练效果。

> 【补充解答】  
>
> - 为什么要每 30-45 分钟重新标定？  
> 答：主要为降低外参漂移带来的误差。在长时间录制或多次操作中，轻微撞击、温度变化、相机抖动等会让机械臂末端到相机的标定关系发生微小变化，积累后影响定位精度。所以需要定期标定，保证采集/控制的一致性和准确性。
> - 标定发生在 VLA 推理阶段吗？  
> 答：标定过程本身与 VLA 推理分开进行，标定是在数据采集准备阶段（以及周期性插入停顿时）完成，之后以标定结果解算所有后续 episode 的视觉外参。VLA 推理实用的是最近一次的有效标定参数。
> - 标定怎么做？是“手在眼”吗？  
> 答：这里采用典型的 “hand-eye calibration”（手-眼标定）方法，即机械臂末端夹持一个有标靶（如棋盘格、圆点阵等）的标定板，通过多组已知机械臂位姿下的相机观测，采用经典 hand-eye 算法（如 Tsai-Lenz / Daniilidis 算法）解算相机外参。流程是：将标定板固定在机械臂末端，机械臂运动到不同空间姿态，每到一个点拍照记录，然后用相关标定软件解算目标相机在机械臂末端的外参矩阵。这套做法比只做相机本身的内参/标定（如相机标定板静止不动）更能保证真实的“末端-相机”空间关系精度。

## 五、模仿学习微调（Phase 1）



### 5.1 训练环境


| 项              | 配置                                                 |
| -------------- | -------------------------------------------------- |
| 代码基座           | `openpi` PyTorch + LeRobot `pi0.5` policy          |

| 框架             | PyTorch 2.3 + CUDA 12.1                            |
| 精度             | **bfloat16** + gradient checkpointing              |
| 有效 batch size  | **64**（per-GPU 8 × accum 4 × 2 GPU）                |
| 训练步数           | **80k steps**（≈ 18 epoch，early stop 于 val loss 平台） |
| wall time      | **~14 h**                                          |




### 5.2 超参数明细

```yaml
# config/origami_pi05_il.yaml（实际使用配置摘要）

model:
  type: pi05
  pretrained_path: lerobot/pi05_base
  action_dim: 26
  action_horizon: 50
  num_inference_steps: 10        # Flow Matching ODE 步数

optimizer:
  type: adamw
  lr_action_expert: 1.0e-4
  lr_lora: 3.0e-5
  weight_decay: 1.0e-4
  warmup_steps: 2000
  cosine_decay: true

lora:
  enabled: true
  rank: 16
  alpha: 32
  target_modules: [q_proj, v_proj]   # 仅 PaliGemma 顶层 4 层
  freeze_vlm_below_layer: 14

training:
  batch_size: 8                      # per GPU
  gradient_accumulation: 4
  max_steps: 80000
  save_every: 5000
  val_ratio: 0.05                    # 按 episode 划分，防泄漏
  seed: 42

augmentation:
  color_jitter: {brightness: 0.1, contrast: 0.1, saturation: 0.05}
  random_crop: 0.95                  # 轻量，避免裁掉纸角
  # 不对折痕线做 heavy aug

loss:
  type: flow_matching_velocity
  # L = E[ || v_θ(x_t, t|obs) - (x_1 - x_0) ||² ]
```

| Val action MAE（deg，L6 指节） | —          | **4.8°**     |


**指标说明：**

- **Train FM loss / Val FM loss**：Flow Matching velocity 损失，是模型输出的动作速度 field 与真实动作速度 field 的均方误差（MSE），反映轨迹学习的拟合质量。Train 表示训练集，Val 表示验证集。
- **Val action MAE（deg，臂关节/L6指节）**：动作均值绝对误差（Mean Absolute Error, 单位为度）。分别统计机器人臂部各关节与 L6（指节模组）各自由度的动作预测与真实演示的角度偏差，数值越低说明模型复现专家动作越精准。其中 L6 指节行程更小、更细腻，因此 MAE 往往略高属于正常。

> 指节 MAE 更大是预期内的：L6 行程小、量化分辨率高，且示教本身方差大。



### 5.4 IL 完成后各阶段成功率（Isaac Sim）


| 子任务            | IL-only 成功率 |
| -------------- | ----------- |
| align（对准纸边）    | 78%         |
| pinch（双指捏边）    | 62%         |
| fold（翻折）       | 55%         |
| crease（压折痕）    | **41%**     |
| **完整 episode** | **38%**     |


瓶颈在 **crease**：需要精确法向力，纯位置模仿学不到。

## 六、仿真验证与 Sim-to-Real 问题



### 6.1 Isaac Sim 场景搭建

```
URDF：dual_arm_l6.urdf（双臂 + 双手，Paper 为 USD Deformable，USD Deformable 指的是采用 USD（Universal Scene Description）格式定义的可变形体模拟，能够很好地模拟纸张等柔性物体的弯曲、折叠和受力形变效果，适用于需要高度物理真实性的场景建模）
├── 纸张：PhysX deformable sheet，弯曲刚度调参 3 轮
├── 摩擦：paper-table μ=0.45，finger-paper μ=0.6
├── Domain Randomization：
│   ├── 纸色 HSV ±10
│   ├── 初始位姿 ±5 cm / ±20°
│   ├── 摩擦 ±20%
│   └── 相机 exposure ±15%
└── ros2_control 插件 → 与真机同一推理 node
```



### 6.2 Sim-to-Real 主要问题与优化



#### 问题 1：纸张滑动（最严重）

| 现象 | 压折时纸整体平移 1–3 cm，折痕歪 |
| 根因 | IL 只模仿位置，未建模摩擦；L6 力控未接入 VLA |
| 优化 | ① crease 阶段降低臂速 50%；② L6 拇指+食指预紧力固定 3N（SDK 力矩限幅）；③ 数据增采 40 条「慢速压折」demo |

#### 问题 2：柔性形变 sim gap

| 现象 | Sim 38% → 真机首测 **12%** |
| 根因 | PhysX deformable 与 A4 纸差异大 |
| 优化 | 不追求 sim 绝对成功率，改用 sim 做 **相对排序** + DR；真机以 SAC 为主提升 crease |

#### 问题 3：相机外参漂移

| 现象 | 腕部相机振动后，pinch 阶段指尖对不准纸边 |
| 根因 | 7DOF 臂快速运动时腕部相机 TF（Transform，坐标系变换）滞后，TF 即相机与机器人各连杆/基座之间的空间姿态与位置的变换关系 |
| 优化 | ① 每 episode 开头 2 s 用 ArUco 纸面标记做 online extrinsic refine；② pinch 段改用 **top + 左腕** 双视角，去掉右腕（被臂遮挡多） |

#### 问题 4：推理延迟 vs 50Hz 控制

| 现象 | 单步 VLA 110 ms，50Hz   20ms跟不上 |
| 根因 | PaliGemma prefix 每 replan 重算 |
| 优化 | ① **KV cache 复用**：8 步内只重算 suffix ODE（注：suffix ODE 指的是 Transformer 解码时，仅在上下文后缀 token 重新推理一次动作序列的常微分方程结构，非全序列重算）；② FP16 + `torch.compile`；③ 实际控 **25Hz 执行 + 50 步 chunk 插值（常用线性插值，将8步replan结果平滑插入50步控制，以补齐输出频率）**

#### 问题 5：双臂碰撞

| 现象 | fold 阶段偶发臂-臂碰撞 |
| 根因 | VLA 无显式碰撞约束 |
| 优化 | 这一步的意思是：在模型（VLA）推理出机械臂关节的动作增量（Δq）之后，并不会直接把这些动作下发给机器人执行。为了避免双臂在操作过程中相互碰撞，我们在动作下发前，再加一道“保险”——用 MoveIt2 做一个很简单、快速的碰撞检查和动作裁剪。
具体流程是：先检查预测出来的关节动作是否超出了机械臂的运动范围（joint limit），再使用 MoveIt2 的碰撞检测功能，对本次动作后双臂、双手、纸张等对象之间是否存在碰撞进行检测。此处采用的碰撞检测是 MoveIt2 的标准离散碰撞检测（discrete collision checking），对于每一步的动作规划，均会在当前和目标状态之间调用该接口判断是否发生自碰或与环境的碰撞。如果发现有超限或检测到碰撞风险，就把本次动作的幅度缩小一半（scale 0.5），以降低碰撞发生率。整个过程调用轻量，延迟可控，能够在物理层面对模型推理可能出现的风险起到有效保护作用。

#### 问题 6：L6 指节饱和

| 现象 | 某些姿态下 L6 第 3 指节打限位，纸未夹紧 |
| 根因 | 示教者习惯性外展过大，分布外 |
| 优化 | action 后处理 clamp + SAC reward 加「指节限位惩罚」

### 6.3 Sim-to-Real 优化后（IL-only，真机）


| 指标             | 优化前      | 优化后           |
| -------------- | -------- | ------------- |
| 完整 episode 成功率 | 12%      | **34%**       |
| crease 子步成功率   | 8%       | **28%**       |
| 单 episode 平均时长 | 失败前 38 s | 成功平均 **61 s** |


> IL + 工程优化到 34% 后触顶，促使引入 SAC。

## 七、SAC 后训练引入（Phase 2）



### 7.1 为什么选 SAC（而非 PPO / GRPO）


| 算法      | 本项目取舍                                                           |
| ------- | --------------------------------------------------------------- |
| **SAC** | ✅ 连续 26 维动作；off-policy 复用 3h demo + rollout；最大熵利于 crease 探索不同指力 |
| PPO     | on-policy，真机 sample 太贵                                          |
| GRPO    | 适合同 prompt 多采样比较；折纸 contact 奖励稀疏，组内方差不够                         |


与 [02-VLA与RL进阶 §4.3](../theory/02-VLA与RL进阶.md#43-完整示例机械臂抓取-放置任务的-rl-后训练) 中 RECAP 流程对齐，但本项目 **critic 可微**，接触奖励可 shaping，SAC 更直接。

### 7.2 RL 引入时机与数据

```
IL checkpoint（34% 真机成功率）
        ↓
真机自主 rollout 10 天（每天 ~2h 机时）
        ├── 成功 trajectory：412 条
        ├── 失败 trajectory：891 条
        └── 人工干预修正（DAgger）：63 条
        ↓
Replay Buffer：1.2M transitions（含 3h demo 全部重放权重 ×2）
```

**关键设计**：SAC **不是从零训**，而是以 IL 的 Action Expert 权重初始化 Actor，Critic 随机初始化。

### 7.3 状态 / 动作 / 奖励定义

**状态** $s_t$（Critic 输入，256 维压缩）：

```python
s_t = concat([
    proprio_26,                    # 关节角
    vla_latent_pooled,             # Action Expert 倒数第二层 mean pool → 128d
    phase_onehot,                  # align/pinch/fold/crease
    last_action_26,                # 上一步执行动作
])
```

**动作** $a_t$：Actor 输出 **残差** $\Delta a_t$，叠加 VLA 基准动作：

$$a_t^{exec} = a_t^{VLA} + \alpha \cdot \Delta a_t, \quad \alpha=0.3 \text{（前 20k step）→ 0.5}$$

这样 RL 只学「修正量」，避免破坏 IL 已学到的 coarse 轨迹。

**奖励**：


| 事件                      | 奖励                   |
| ----------------------- | -------------------- |
| 完整折纸成功                  | **+10.0**            |
| 完成子步（ArUco 检测折痕角度 < 5°） | +1.0                 |
| 纸张滑出工作区                 | -2.0                 |
| 臂-臂碰撞                   | -1.5                 |
| L6 指节限位                 | -0.3                 |
| 每步时间                    | -0.005               |
| crease 阶段法向力在 [2N, 5N]  | +0.1 / step（shaping） |




### 7.4 SAC 网络结构

```
Actor（初始化 = IL Action Expert 权重）
├── 输入：VLA prefix KV cache + 当前 proprio
├── 结构：Gemma-300M Action Expert（与 IL 同构）
├── 输出：Δa ~ Tanh-Gaussian，26 维
└── 可训练参数：~300M（VLM 全冻结）

Critic × 2（双 Q，各 3 层 MLP）
├── 输入：s_t (256) + a_t (26) → 256
├── 隐藏层：[512, 512, 256]
└── 输出：标量 Q 值

Target Critic：Polyak τ=0.005 软更新
```



### 7.5 SAC 训练配置


| 项             | 配置                                                              |
| ------------- | --------------------------------------------------------------- |
| GPU           | **1 × NVIDIA A100 80GB**（Critic + Actor 同卡；4090 上 batch 32 OOM） |
| 算法            | SAC，自动温度 $\alpha$，target entropy = -26                          |
| Actor lr      | **3e-5**（小于 IL，防灾难性遗忘）                                          |
| Critic lr     | **1e-4**                                                        |
| Batch size    | **512**                                                         |
| Replay buffer | 1.2M，demo 比例 30%                                                |
| 训练步数          | **150k gradient steps**                                         |
| 更新比例          | 每 1 真机 episode → 50 gradient steps（sim 中预训 80k step）            |
| $\gamma$      | 0.99                                                            |
| 知识隔离          | **PaliGemma + LoRA 全冻结**；仅 Actor（Action Expert）更新               |


```yaml
# sac_posttrain.yaml 摘要
sac:
  gamma: 0.99
  tau: 0.005
  initial_alpha: 0.2
  auto_alpha: true
  target_entropy: -26
  residual_scale: 0.3          # → 0.5 after 20k steps

training:
  critic_warmup_steps: 5000     # 先训 Critic，Actor 冻结
  actor_start_step: 5000
  total_steps: 150000
  eval_every: 5000
  save_every: 10000

sim_pretrain:
  enabled: true
  steps: 80000                  # Isaac Sim 里先跑 80k，再上真机
  domain_randomization: true
```



### 7.6 RL 引入的三阶段流程（实际执行顺序）

```
Stage A — Sim SAC 预训练（3 天）
  IL policy 固定为 "teacher"
  Actor 学 residual 修正 sim 中的 crease
  Sim 成功率 38% → 61%

Stage B — 真机 rollout 收集（10 天）
  混合执行：ε-greedy 探索，ε 从 0.3 衰减到 0.05
  失败轨迹高权重入 buffer（priority sampling）

Stage C — 真机 SAC 微调（5 天）
  每早 sim eval → 白天真机 20 episode → 夜间 offline 50k grad steps
  循环 3 轮
```



### 7.7 SAC 训练日志（关键指标）


| 步数              | Sim 成功率 | 真机成功率   | 平均 Q    | 策略熵     |
| --------------- | ------- | ------- | ------- | ------- |
| 0（IL-only）      | 38%     | 34%     | —       | —       |
| 50k             | 55%     | 41%     | 2.1     | 8.4     |
| 80k（sim 预训完）    | 61%     | —       | 3.8     | 6.2     |
| 120k            | 58%     | 52%     | 5.2     | 5.1     |
| **150k（final）** | **57%** | **58%** | **6.0** | **4.6** |


> Sim 略降（57% vs 61%）是真机数据分布进入后的正常 trade-off；真机 crease 从 28% → **54%**，提升最大。

## 九、经验总结与面试话术



### 9.1 三句话项目介绍

> 我做了一个 **双臂 + Linker Hand L6** 的折纸任务：用 **π0.5**（PaliGemma + Flow Matching Action Expert）在 **3 小时**遥操作数据上做 IL 微调，**2×4090 训约 14 小时**；真机 IL 只有 34%，主要卡在 **crease 接触**。通过 **ArUco 在线标定、MoveIt 安全 clip、L6 预紧力** 做 sim2real 工程优化后，引入 **SAC 残差后训练**——**冻结 VLM、只更新 Action Expert**，在 **A100** 上 150k step，真机成功率到 **58%**，crease 子步从 28% 提到 54%。



### 9.2 高频追问速答


| 追问                   | 要点                                             |
| -------------------- | ---------------------------------------------- |
| 3 小时够吗？              | IL 够启动，不够鲁棒；RL 阶段补了 1300+ rollout              |
| 为什么 SAC 不直接训 VLA 全参？ | 知识隔离，防语言/视觉能力被 RL 梯度破坏                         |
| SAC 和 VLA 怎么结合？      | **残差策略**：$a = a^{VLA} + \alpha \Delta a^{SAC}$ |
| sim2real 最大 gap？     | **纸柔性 + 摩擦**；sim 做 DR 和相对验证，不靠 sim 绝对成功率       |
| 为什么不用 RECAP/GRPO？    | 接触奖励可 dense shaping，SAC 双 Q 更稳；GRPO 适合语言推理类    |




### 9.3 若重做会改什么

1. **crease 阶段早接入力控** — 省 SAC 一半探索预算
2. **DAgger 与 RL 并行** — 63 条干预数据性价比极高，应系统化
3. **子任务独立 checkpoint** — 4 段分别微调再 compose，减少长程 drift
4. **RTC（Real-Time Chunking）** — π0.5 官方推理优化，进一步降延迟
