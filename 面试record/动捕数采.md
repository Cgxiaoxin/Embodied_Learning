### 1.2 商业模式（两个字母）

| 代号 | 全称 | 内容 |
|------|------|------|
| **Project T** | Tele-operation 遥操作 | 动捕设备 + 遥操作框架（Tele-Op）+ 端侧配套；销售给机器人厂商做示教数采 |
| **Project D** | Data factory 数据工厂 | 规模化多模态数据采集、处理、标注、交付；In-the-factory（ITF）+ In-the-wild（ITW） |

**客户覆盖：** 国内近 30 家机器人厂商（智元、小鹏鹏行、字节、腾讯、达摩院等）；海外头部人形团队；2025 年前 8 个月签单数千万。

**核心观点（戴若犁 GAIR 2025 / 界面新闻）：**

- 遥操作数采中，**连续性与鲁棒性 > 绝对精度**；厘米级精度通常够用，「人在流程中」保障末端交互
- 惯性动捕是多数头部企业的**第一选择**（数据不中断、抗遮挡、环境适应强）
- 光学动捕是室内高精度「金标准」，但遮挡 / 异构刚体是行业难题
- **HybridTrack（光惯混合）** 是规模化遥操作数采的进阶解法：光学补末端精度，惯性补抗遮挡
- 数据工厂单日单席目标约 **100 条有效数据**；质量差 → 删采重录，隐性成本极高

## 二、动捕技术速览（零基础补课）

### 2.1 三大技术路线

```
┌─────────────────────────────────────────────────────────────┐
│  惯性动捕（IMU）                                              │
│  穿戴传感器 → 角速度/加速度/磁场 → 卡尔曼滤波 + 骨骼模型     │
│  优点：便携、抗遮挡、数据连续    缺点：漂移、无绝对位置精度     │
├─────────────────────────────────────────────────────────────┤
│  光学动捕（Optical）                                          │
│  多红外相机 → 识别 Marker 圆心 → 三角化 3D 位置              │
│  优点：亚毫米精度、绝对位置      缺点：遮挡、环境限制、成本高   │
├─────────────────────────────────────────────────────────────┤
│  光惯混合（HybridTrack）                                      │
│  IMU 提供连续姿态 + 光学提供关键点位姿闭环                    │
│  诺亦腾核心差异化能力，面向规模化遥操作数采                   │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 惯性动捕工作流程

1. **传感器标定**：静止状态下校准零偏、比例因子
2. **穿戴与拓扑**：传感器绑定骨骼节点，建立人体运动学树
3. **实时解算**：陀螺仪积分 + 加速度计修正重力 + 磁力计修正航向（易受干扰）
4. **骨骼 FK/IK**：从传感器姿态推算全身关节角
5. **后处理**：漂移校正、 foot sliding 消除、平滑滤波

**诺亦腾「磁免疫」升级（PN Link）：** 硬件抗磁 + 多源融合自适应滤波 + 骨骼动力学约束 + 可选光学闭环。

### 2.3 遥操作数采典型 Pipeline

```
操作员穿戴动捕 → 动作重定向到机器人模型 → 机器人执行 + 多相机录制
    ↓
同步记录：关节角 / 末端位姿 / 图像 / 力矩 / 任务标签
    ↓
实时质检（连续性、异常检测）→ 入库 → 标注 / 筛选 → 训练集交付
```

**戴若犁关键洞察：** 动捕在遥操作中更像「符合人类自然动作的遥控器（joystick）」，而非毫米级金标准量测设备。

## 三、安努智能 · 穿戴式多模态数采（高度相关）

> 原题见 [面试复盘 · 安努智能](./面试复盘.md#安努智能)；完整知识见 [面试知识储备 §12–§14](./面试知识储备.md#12-穿戴设备多相机动态标定)

### 3.1 多摄像头动态标定

**题意：** 头部、髋部、手部等非固定相机，在人体运动下如何统一标定？

**与机器人标定的核心差异：**

| 维度 | 机器人 | 穿戴设备 |
|------|--------|----------|
| 参考系 | 刚体固定 | 非刚性、时变 |
| 外参 | 一次标定长期有效 | 穿戴松紧导致漂移 |
| 实时性 | 可离线 | 数采/遥操作需实时融合 |

**推荐两层架构：**

```
第一层：各相机 → 身体局部坐标系（髋部为锚点）
  · 方案 A：CAD 初值 + Charuco/AprilTag 离线精标定
  · 方案 B：头显 VIO/SLAM + 头-髋运动学约束

第二层：手眼标定（以头部为基准求 T_head^hand）
  · AX = XB（Tsai-Lenz / 对偶四元数）
  · 共视 ArUco / 骨架点做在线修正
  · 重投影误差突增 → 触发重标定
```

**30 秒话术：**

> 拆两层：先把各相机挂到身体系（髋部锚点），再以头部为基准做手眼标定。人体是动态参考系，外参需在线维护，共视标记或骨架点修正，穿戴松动靠重投影误差触发重标。难点在非刚性、外参时变和实时性。

**与诺亦腾场景的关联：** Tele-Op 常配头显 + 手套相机 + 第三人称相机；Adam-U 等多模态平台必然涉及类似标定问题。

### 3.2 多设备时间戳同步

**不同步来源：** 独立晶振漂移、USB/WiFi/蓝牙延迟、OS 调度、rolling shutter、采样率不一致（IMU 1 kHz vs 相机 30 Hz）。

**四层策略：**

| 层级 | 方案 | 精度 |
|------|------|------|
| L1 硬件 | GPIO 触发、共享时钟、PTP (IEEE 1588)、USB 集中采集 | 最优 |
| L2 时钟 | 启动闪光/拍手估 offset；IMU-视觉互相关 | 亚毫秒~毫秒 |
| L3 数据 | 主从时钟 + 最近邻/线性插值/slerp；ROS2 ApproximateTime | 工程必做 |
| L4 内容 | 视觉特征 / 音频互相关估延迟 | 兜底 |

**动态人体额外注意：**

- Rolling shutter：手快速挥动需 RS 校正或提高快门
- 无线手相机：**采集端打戳**，非接收端
- 对齐位姿，不只对齐图像；> 30–50 ms 偏移会明显损 VLA 精度

**30 秒话术：**

> 能硬件触发或 PTP 最好；否则启动时闪光估 offset，运行中 IMU-视觉互相关慢更新。数据层以头显为主时钟，手/髋用插值对齐。无线设备必须端侧打戳。

**与诺亦腾场景的关联：** PN Link 有线规避射频干扰；多席位工厂数采对时间同步要求更严；动捕 240 Hz + 相机 30 Hz + 机器人 1 kHz 控制需统一时间基准。

### 3.3 模型推理加速与量化

**题意：** 数采现场或 Tele-Op 端侧可能跑感知模型（手势、物体检测）；量化后如何控精度损失？

**部署链路：** PyTorch → ONNX → TensorRT；先 FP16，不够再 INT8 PTQ。

**控精度手段：**

1. 校准集用**真实场景**分布（200–1000 张）
2. 敏感层（首层、末层、head）保留 FP16
3. per-channel 权重量化
4. 掉点明显 → QAT / 蒸馏
5. 机器人场景看**端到端成功率**，不只看 mAP

**与诺亦腾场景的关联：** 数据工厂可能含在线质检、实时预览、端侧推理；Tele-Op 低延迟要求与 VLA 部署思路相通（见下节）。

## 四、浙江滴石 · 轨迹与实时系统（数采后处理相关）

> 原题见 [面试复盘 · 浙江滴石](./面试复盘.md#浙江滴石技术有限公司)；完整知识见 [面试知识储备 §15](./面试知识储备.md#15-轨迹插值拟合与实时检索)

### 4.1 插值 vs 拟合

| | **插值** | **拟合** |
|---|----------|----------|
| 目标 | 已知起终点，**补中间点** | 从带噪采样**反推**光滑曲线 |
| 是否过点 | 严格过控制点 | 一般不过每点 |
| 场景 | 实时执行、MoveIt 笛卡尔直线 | 示教降噪、离线优化 |
| 例子 | LERP、三次样条、minimum jerk | 最小二乘、B 样条、Savitzky-Golay |

**直线插值：** 从 A 到 B 按时间/弧长补点 → 轨迹连贯，是参数化直线，≠ 拟合最优曲线。

### 4.2 为什么轨迹都是离散点？

- 控制周期固定（1 ms / 4 ms）
- 传感器采样率有限（动捕 60–240 Hz，相机 30 Hz，编码器 1 kHz）
- 存储与通信按帧打包

物理连续，数字系统必然离散；光滑性靠插值/拟合重建。

### 4.3 离散 → 平滑：常见算法

| 方法 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| 三次样条 | C² 连续 | 需解方程组 | 关节轨迹 |
| B 样条 | 局部可控 | 参数复杂 | 复杂路径 |
| Minimum Jerk | 符合人类运动学 | 需边界条件 | 抓取接近 |
| Savitzky-Golay | 保峰值、可在线 | 需选窗口 | **动捕实时滤波** |
| 高斯过程 | 不确定性估计 | 计算贵 | 小数据 |

### 4.4 实时系统快速找轨迹

```
离线：demo 建索引（KD-tree / FAISS）
  ↓
在线：当前状态 → 检索 Top-K 相似 demo → warm-start
  ↓
局部：样条插值 / DTW 时间对齐 → 可执行轨迹
  ↓
兜底：RRT 以检索结果为初值，限时迭代
```

**工程提速：** motion primitives 预计算；Action chunking；VLA 低频 + 底层 1 kHz 插值跟踪。

### 4.5 VLA 预训练 + 实时推理协同

| 方案 | 做法 | 延迟 |
|------|------|------|
| 分层异步 | VLA 2–10 Hz 出 subgoal；底层 PD 500 Hz–1 kHz | 低 |
| Action Chunking | 一次预测 H 步，执行 k 步后 replan | 中 |
| 模型压缩 | FP16/INT8、蒸馏 | 降推理耗时 |
| Speculative | 小模型先出，大模型异步校正 | 隐藏延迟 |
| Demo 检索 | 相似场景检索轨迹，VLA 只做分类 | 最低 |

**原则：** 大模型管「做什么」，小环管「怎么快」。

### 4.6 权重设计与均值窗口

\[
\hat{x}_t = \frac{\sum_{i=0}^{N-1} w_i \cdot x_{t-i}}{\sum w_i}
\]

| 权重类型 | 特点 | 用途 |
|----------|------|------|
| 等权 | 简单 | 基础平滑 |
| EMA | 近期权重大 | 在线、低延迟 |
| 高斯 | 中心大边缘小 | 保形平滑 |
| 按置信度 | 好帧权重大 | **多传感器融合** |

**窗口 N：** 越大越平滑但滞后越大（≈ N/2 采样周期）。控制环 3–7 点，示教 5–15 点；硬约束是可接受滞后（如 < 20 ms）。

**与诺亦腾场景的关联：** 动捕数据后处理（foot sliding 消除、抖动滤波）；多路传感器融合；Tele-Op 重定向时的平滑与延迟权衡。

## 五、诺亦腾面试高频延伸题

结合公司技术栈与行业实践，除上述原题外，还可能问到：

### 5.1 惯性 vs 光学怎么选？

> 遥操作数采优先**连续性和鲁棒性**：惯性是第一选择；需要末端绝对精度或多人/多物体交互时上**光惯混合**。光学 alone 在遮挡严重的机器人场景（取货、玩魔方）问题很大。

### 5.2 动作重定向（Retargeting）

人体与机器人结构异构（人 ~180 DoF vs 人形 ~40 DoF）：

- 建立骨骼映射表（人关节 → 机器人关节）
- 误差最优 IK：最小化位置/姿态误差 + 正则项（避奇异、限关节）
- 缩放因子：人臂长 → 机器人臂长
- 质心 / 平衡约束（步态场景）

### 5.3 数据质量与 SOP

| 原则 | 说明 |
|------|------|
| 标定优先 | 采集前充分验证外参和时间同步 |
| 实时监控 | 连续性异常当场处理，避免事后删采 |
| 元数据完整 | 设备版本、标定参数、场景 ID、操作员、成功/失败标签 |
| 场景矩阵 | 系统性覆盖，避免长尾偏差 |
| 有效产出 | 熟练操作员 8 h 约 2–3 h 有效数据；单席 ~100 条/日 |

### 5.4 地磁 / 射频干扰怎么处理？

- **磁干扰：** PN Link 磁免疫（硬件 + 算法）；避免大型电机、钢结构的强磁场区域
- **射频干扰：** 有线连接（PN Link）；多席位时用主节点 + 频谱规划；无线版注意 2.4 GHz 拥挤

### 5.5 四元数 vs 欧拉角（动捕必考基础）

| | 欧拉角 RPY | 四元数 |
|---|-----------|--------|
| 优点 | 直观 | 无万向节锁、slerp 平滑 |
| 缺点 | 万向节锁、插值差 | 不直观 |
| 动捕用法 | UI 显示 | **内部存储、骨骼旋转插值、重定向** |

### 5.6 ROS2 在数采中的应用

- Topic：关节角、图像、IMU 流式发布
- `rosbag2` 录制多模态数据
- `message_filters` ApproximateTime 同步
- TF2：动捕坐标系 → 机器人 base_link 变换链
- QoS：传感器数据 Best Effort + 大 History
