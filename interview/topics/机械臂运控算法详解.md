## 三、正运动学 FK

### 3.0 一句话定义

**正运动学（FK）**：已知各关节角 `q = [q1,…,qn]`，求末端执行器（TCP）相对于基座的位姿 `T_base^tcp ∈ SE(3)`。

**面试一句话：** FK 是「关节角 → 末端位姿」，沿连杆链连乘齐次变换，O(n) 复杂度，确定性、唯一解。

### 3.1 核心公式与 DH 变换

**连杆变换（Modified DH 常用）：**

相邻连杆 `i-1 → i` 的 4×4 齐次变换：

```
T_{i-1}^{i}(θ_i) = Rot_z(θ_i) · Trans_z(d_i) · Trans_x(a_i) · Rot_x(α_i)
```

**正运动学链式乘法：**

```
T_base^tcp = T_0^1(q1) · T_1^2(q2) · … · T_{n-1}^n(qn) · T_tool
```

- `T_tool`：法兰到 TCP 的固定变换（夹具、焊枪偏移）
- 旋转关节：`θ_i = q_i`（变量）；移动关节：`d_i = q_i`

**DH 两种约定对比（面试常问）：**

| 项目 | Standard DH | Modified DH |
|------|-------------|-------------|
| 坐标系附着 | 连杆 i 末端 | 连杆 i 始端 |
| 变换顺序 | 先 θ 后 d 再 a 再 α | 先 θ 后 d 再 a 再 α（顺序不同） |
| 工程使用 | 教材多 | ROS/KDL/Pinocchio 多 |

### 3.2 实现流程（逐步）

```
输入：关节角 q[1..n]，DH 参数表，T_tool
    ↓
Step 1：初始化 T = I（4×4 单位阵）
    ↓
Step 2：for i = 1 to n
         根据关节类型取 θ_i 或 d_i
         查表得 (a_i, α_i, d_i)
         计算 T_{i-1}^i
         T = T · T_{i-1}^i        ← 左乘或右乘取决于约定，保持一致
    ↓
Step 3：T = T · T_tool           ← 法兰 → TCP
    ↓
Step 4：从 T 提取位置 (x,y,z) 和姿态 (R 或四元数)
    ↓
输出：T_base^tcp
```

**递归 vs 迭代：**

| 方式 | 做法 | 场景 |
|------|------|------|
| 迭代 | 循环连乘 n 个变换矩阵 | 通用，O(n) |
| 递归 | 树形结构（分支臂） | 双臂、并联简化模型 |
| 缓存 | 只变部分关节时复用中间 T | 实时控制优化 |

### 3.3 代码实现思路

**自研（C++/Python 伪代码）：**

```python
def fk(q, dh_table, T_tool=np.eye(4)):
    T = np.eye(4)
    for i, qi in enumerate(q):
        a, alpha, d, theta_offset = dh_table[i]
        theta = qi + theta_offset          # 旋转关节
        T_i = dh_transform(a, alpha, d, theta)
        T = T @ T_i
    return T @ T_tool
```

**库实现：**

| 库 | 接口 | 说明 |
|----|------|------|
| KDL | `ChainFkSolverPos_recursive` | 轻量，MoveIt 默认 FK |
| Pinocchio | `forwardKinematics(model, data, q)` | 高效，顺带更新 Jacobian |
| MoveIt | `RobotState::getGlobalLinkTransform(link)` | 内部调 KDL，带 TF 树 |

**Pinocchio 典型用法：**

```cpp
pinocchio::forwardKinematics(model, data, q);
pinocchio::updateFramePlacements(model, data);
SE3 T = data.oMf[frame_id];  // 末端 frame 位姿
```

### 3.4 多坐标系与姿态表示

**TF 树关系：**

```
world → base_link → link1 → … → link_n → flange → tool → camera
```

**FK 在控制链路中的用途：**

| 用途 | 说明 |
|------|------|
| IK 验证 | 解出 q 后 FK 回代，检查位姿误差 < ε |
| 碰撞检测 | FK 得各 link 位姿 → FCL 碰撞几何变换 |
| Jacobian | FK 递推同时算各关节轴向量 |
| 重力补偿 | G(q) 需要各连杆质心位置 → 依赖 FK |
| 视觉映射 | 相机坐标点经 TF 变换到 base |

**姿态表示选型：**

| 表示 | 优点 | 缺点 | 使用场景 |
|------|------|------|----------|
| 旋转矩阵 R | 无奇异性 | 9 参数冗余 | 内部计算 |
| 四元数 | 紧凑、插值 slerp 平滑 | 双覆盖 ±q | **存储、插值、控制** |
| 欧拉角 RPY | 直观 | 万向节锁 | **仅显示** |

**面试话术：** 「内部用旋转矩阵/四元数，欧拉角只做显示；插值一定用四元数 slerp，不用欧拉角线性插。」

### 3.6 高频追问快答

**Q：FK 和 IK 哪个难？**  
A：IK 难。FK 唯一解、确定性；IK 可能无解、多解、数值不收敛。

**Q：Modified DH 和 Standard DH 怎么选？**  
A：跟 URDF/厂商文档一致即可；ROS 生态多用 Modified DH；关键是全链路统一，不能混用。

**Q：FK 误差从哪来？**  
A：DH 参数标定误差、关节编码器误差、传动间隙（半闭环不可测）、柔性变形。FK 本身无算法误差，误差在模型和传感。

**Q：怎么验证 FK 实现正确？**  
A：零位姿态手算对比；随机 q 与 Pinocchio/KDL 交叉验证；已知末端位置用激光跟踪仪实测。

## 四、逆运动学 IK（全解法）

> 湃特纳、零次方、赛博格均深挖 IK；需能按「解法分类 → 流程 → 适用场景 → 失败处理」完整讲清。

### 4.1 解法分类总览

| 类别 | 代表方法 | 速度 | 通用性 | 多解处理 | 面试常问 |
|------|----------|------|--------|----------|----------|
| **解析/几何法** | Pieper 6DOF、臂角法 7DOF | μs 级 | 结构受限 | 显式枚举 | 流程、限位筛选 |
| **数值迭代法** | Jacobian 伪逆、DLS、LM | ms 级 | 通用 | 依赖 seed | 收敛、奇异 |
| **优化法** | NLopt、CasADi+Pinocchio | ms–s 级 | 通用+约束 | 代价函数选解 | 约束建模 |
| **库封装** | KDL LMA、Trac-IK、MoveIt IK | ms 级 | 通用 | 多 seed | 与自研配合 |

**选型决策树：**

```
机器人结构满足 Pieper 条件（后三轴交于一点）？
    ├── 是 → 解析 IK 主路径（快、确定）
    └── 否 → 7DOF 冗余？
              ├── 是 → 臂角法 / 固定冗余角降维 / 零空间优化
              └── 否 → 数值 IK（DLS/LM）+ 多 seed
                        └── 有复杂约束 → 优化 IK
```

### 4.2 解析几何法（6DOF Pieper 型）

**适用条件（Pieper 准则）：** 6 关节中后 3 轴（腕部）轴线交于一点 → 可将位置与姿态解耦。

**以 6DOF 球腕机械臂为例，详细流程：**

```
输入：目标位姿 T_target（位置 p_d + 姿态 R_d），当前 seed（选解用）
    ↓
Step 1：剥离工具变换
    T_wrist = T_target · inv(T_tool)
    ↓
Step 2：求腕心位置 p_w（wrist center）
    p_w = p_d - d_6 · R_d · z_axis     ← 沿末端 z 轴回退 d_6
    ↓
Step 3：求肩肘关节 q1, q2, q3（位置解耦）
    - q1 = atan2(p_w.y, p_w.x)          ← 绕基座 z 转角
    - 在臂平面内用几何法解 q2, q3（余弦定理，两解：肘上/肘下）
    ↓
Step 4：计算腕部旋转矩阵
    R_0^3 = FK(q1,q2,q3) 的旋转部分
    R_3^6 = inv(R_0^3) · R_d            ← 腕部需实现的旋转
    ↓
Step 5：从 R_3^6 解 q4, q5, q6（欧拉角/ZYZ 分解）
    - 注意万向节锁：q5 ≈ 0 时 q4+q6 耦合
    ↓
Step 6：多解枚举与筛选
    - 肘上/肘下 × 腕部翻转 → 最多 8 组解
    - 过滤：关节限位、与 seed 最近、避奇异
    ↓
输出：q_best 或 NO_SOLUTION
```

**多解示意：**

| 分支 | 含义 | 工程选取策略 |
|------|------|--------------|
| 肘上 vs 肘下 | 手臂形态 | 选与当前姿态最近 |
| 腕部翻转 | q4/q6 组合不同 | 避免腕部奇异 |
| 限位外 | 物理不可达 | 直接丢弃 |

**面试话术：** 「6DOF 球腕臂用 Pieper 分解：先几何解肩肘定腕心，再解腕部三角；枚举 8 解后按限位和与上一帧最近选解。」

### 4.3 臂角法（7DOF 冗余臂）

**冗余原因：** 7 关节对 6D 位姿（3 位置 + 3 姿态）多 1 自由度 → 无穷多解，自运动（self-motion）。

**臂角 ψ 物理含义：** 肩-肘-腕 三点构成的臂平面，绕肩-腕连线旋转的角度。固定 ψ 后，7DOF 降为 6DOF，可用解析法。

**臂角法详细流程：**

```
输入：T_target，臂角 ψ（或等价：冗余关节目标如 q4）
    ↓
Step 1：确定臂角 ψ
    - 由任务指定（保持肘部朝外）
    - 或由上一帧 q 计算保持连续
    - 或优化：min |q - q_prev|
    ↓
Step 2：利用 ψ 构造臂平面法向量
    肩位置 S、腕心 W 已知 → 臂平面绕 S-W 轴旋转 ψ
    ↓
Step 3：在臂平面内解 q1, q2, q3（类似 6DOF，多一个自由度参数）
    ↓
Step 4：解冗余关节 q4（或中间关节，取决于构型）
    ↓
Step 5：解腕部 q5, q6, q7
    ↓
Step 6：验证 FK(q) ≈ T_target，检查限位
    ↓
输出：q 或失败
```

**固定 q4 降维法（工程常用简化）：**

```
固定 q4 = q4_ref（如保持肘关节角度）
    ↓
7DOF → 6DOF 子问题
    ↓
用 6DOF 解析/数值 IK 求解其余 6 关节
    ↓
迭代调整 q4 直到误差收敛（或 q4 作为外层优化变量）
```

**零空间利用（与臂角法互补）：**

```
Δq = J⁺ Δx + (I - J⁺J) · z

Δx：末端位姿误差修正（任务空间）
z：零空间优化目标（臂角、避障、远离限位、远离奇异）
(I - J⁺J)：投影到零空间，不影响末端任务
```

### 4.4 Jacobian 数值迭代法

**基本思想：** 在当前 q 处线性化：`Δx ≈ J(q) · Δq`，迭代修正直到 `‖x_ee - x_d‖ < ε`。

**单步迭代流程：**

```
输入：目标 x_d，初始 q_0，最大迭代次数 K，步长 α
    ↓
for k = 0 to K:
    1. x_k = FK(q_k)                    ← 正运动学
    2. Δx = x_d ⊖ x_k                   ← 位姿误差（6D：3位置+3姿态）
    3. if ‖Δx‖ < ε: return q_k          ← 收敛
    4. J = Jacobian(q_k)                ← 6×n 几何雅可比
    5. Δq = α · J⁺ · Δx                 ← 见下方求逆方法
    6. q_{k+1} = q_k + Δq
    7. 关节限位裁剪 / 归一化角度
    ↓
return FAIL（未收敛）
```

**三种求逆方法对比（面试高频）：**

| 方法 | 公式 | 优点 | 缺点 |
|------|------|------|------|
| 伪逆 J⁺ | Δq = J⁺Δx | 简单 | 奇异附近爆炸 |
| 阻尼最小二乘 DLS | Δq = Jᵀ(JJᵀ+λ²I)⁻¹Δx | 奇异附近稳定 | λ 需调参 |
| Levenberg-Marquardt | 自适应 λ，介于 GN 和梯度下降 | 鲁棒收敛 | 稍慢 |

**DLS 面试话术：** 「奇异点附近 JJᵀ 趋近奇异，加 λ²I 正则化保证可逆；λ 大时退化为梯度下降，小则接近伪逆。」

**姿态误差计算注意：** 不用欧拉角相减；用旋转矩阵：`ΔR = R_d · R_k^T`，转轴角/旋量作为 3D 姿态误差。

### 4.5 优化 IK

**当约束复杂时（避障、多目标、冗余优化），建非线性优化问题：**

```
minimize   w_p‖p_ee - p_d‖² + w_R‖R_ee - R_d‖² + w_reg‖q - q_ref‖²
subject to q_min ≤ q ≤ q_max
           碰撞距离(q) ≥ d_safe        ← 可选
           自定义等式/不等式约束
```

**求解器：** IPOPT、NLopt、CasADi + Pinocchio（自动微分梯度）。

**优化 IK 流程：**

```
1. 构造代价函数（位姿误差 + 正则 + 冗余偏好）
2. 加关节限位约束（box constraint）
3. 可选：碰撞约束（signed distance ≥ 0）
4. 初始值 q_0 = seed（上一帧 / home / 多 seed 并行）
5. 求解器迭代 → q*
6. FK 验证误差
```

### 4.6 库封装与生产级组合

| 库 | 算法 | 特点 |
|----|------|------|
| KDL LMA | Levenberg-Marquardt | MoveIt 内置备选 |
| Trac-IK | NLopt + KDL 并行多解 | 比纯 KDL 快且成功率高 |
| MoveIt `/compute_ik` | 插件式 IK | 笛卡尔目标 → goal_state |
| Pinocchio | 可自写优化 IK | 动力学+IK 统一模型 |

**生产级组合方案：**

```
主路径：自研解析 IK（臂角法，7DOF 定制，μs 级）
    ↓ 失败
Fallback 1：Trac-IK / KDL LMA（多 seed）
    ↓ 失败
Fallback 2：优化 IK（复杂约束）
    ↓ 失败
上报 NO_IK_SOLUTION → 换目标 / 放宽姿态 / 关节空间绕路
```

**Seed 选取策略：**

| 策略 | 说明 |
|------|------|
| 上一帧 q_prev | 连续运动首选，保证解连续 |
| 命名姿态 home/ready | 冷启动 |
| 多 seed 并行 | Trac-IK 内部实现，提高成功率 |
| 解析解作 seed | 粗解 + 数值精修 |

**为何自研 + 库并存（面试话术）：**  
「7DOF 臂角法针对自家构型定制，延迟 μs 级、多解策略可控；Pinocchio/KDL 做交叉验证和 fallback；MoveIt IK 用于规划管线笛卡尔目标，不替代实时环。」

### 4.8 高频追问快答

**Q：IK 无解有哪些原因？**  
A：目标超出工作空间；姿态不可达；关节限位；奇异构型；建模错误（DH/URDF 偏差）。

**Q：MoveIt IK 失败 error code？**  
A：`NO_IK_SOLUTION`；处理：换 seed、放宽姿态约束（只约束位置）、增大 timeout、改关节空间目标。

**Q：如何保证 IK 解连续（不跳解）？**  
A：用上一帧作 seed；解析法选最近解；加 `‖q - q_prev‖` 正则；监控关节跳变阈值。

**Q：解析 IK 和数值 IK 误差怎么验？**  
A：FK 回代 `‖T_ee - T_d‖`；位置误差 < 1mm、姿态 < 0.1° 为工程常用指标。

**Q：7DOF 臂为什么需要臂角法？**  
A：多 1 自由度，需指定冗余参数（臂角 ψ 或 q4）才能唯一确定解；否则无穷多解无法直接用于控制。

### 8.3 轨迹规划快问快答（详解）

#### 8.3.1 MoveIt2 完整架构

```
MoveIt2
├── URDF + SRDF（模型、Planning Group、ACM）
├── Planning Scene（机器人 + 障碍）
├── 运动学（IK 解笛卡尔目标）
├── 路径规划（OMPL 等）
├── 碰撞检测（FCL，规划时）
├── 后处理（shortcut + 时间参数化）
└── 执行（FollowJointTrajectory）
```

#### 8.3.2 `plan()` 七步流程

```
① 组装 MotionPlanRequest（start/goal/group/planner）
② Planning Pipeline 调 OMPL
③ OMPL 关节空间采样 → StateValidityChecker → FK + FCL
④ 几何路径（无时间）
⑤ shortcut 简化
⑥ IPTP/TOTG 时间参数化
⑦ JointTrajectory → execute()
```

#### 8.3.3 采样规划器对比

| 算法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| RRT | 单树随机扩展 | 简单 | 慢、路径粗糙 |
| RRTConnect | 双向 RRT | **默认，快** | 非最优 |
| RRT* | 采样 + rewiring | 渐近最优 | 慢 |
| PRM | 预建路图 | 重复查询快 | 首建图慢 |

#### 8.3.4 OMPL 碰撞检测（必背）

> OMPL **不做碰撞**；回调 MoveIt + FCL。规划时几何检测，非执行力控。

- 每个采样 state + 路径插值点都检测
- 一次 plan 可能数万次 FCL 查询 → CPU 200–500ms
- 执行默认信任轨迹；场景变化需 scene monitor 重规划

#### 8.3.5 `computeCartesianPath` 原理

```
for each 笛卡尔步长 step:
    插值下一个末端位姿 p_i
    IK(p_i) → q_i
    碰撞检测(q_i)
    if 失败 or 关节跳变 > jump_threshold: break
fraction = 成功步数 / 总步数
```

#### 8.3.6 规划失败排查

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| NO_IK_SOLUTION | 目标不可达/奇异 | 换 seed、放宽姿态 |
| PLANNING_FAILED | 超时/窄通道 | 增时间、换 RRT*、简化障碍 |
| fraction < 1 | 奇异/碰撞/IK跳解 | 减小 step、加中间点 |
| 执行抖动 | 时间参数化过激 | 降速度、用 TOTG |

#### 8.3.7 面试三句话

1. MoveIt2 = 模型 + 场景 + OMPL 采样 + FCL 碰撞 + 时间参数化 + 执行。  
2. SRDF 用 Setup Assistant 生成 Planning Group 和 ACM。  
3. OMPL 碰撞是规划时回调 FCL，不是执行时实时避障。
