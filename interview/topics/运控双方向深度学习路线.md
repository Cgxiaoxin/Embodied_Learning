## 1.1 正运动学 FK



### 一句话定义

已知关节角 `q`，求末端 TCP 相对基座位姿 `T_base^tcp`。**唯一解、O(n)、确定性。**

### 口述描述

正运动学要回答的问题是：**「给定每个关节转了多少度，末端在空间里的位置和朝向是多少？」**

可以把机械臂想成一串依次铰接的连杆。从基座出发，第一关节转 q1，就把第一个连杆相对于基座的姿态定下来；再转 q2，是在 q1 已经转过的基础上再叠一层变换……这样从关节 1 一直乘到关节 n，就得到末端法兰相对基座的位姿。如果手上还有夹具或工具，最后再乘一个固定的工具变换 T_tool，才得到真正的 TCP（工具中心点）。

实际实现中，每一节连杆的位置和姿态，都用一个**4×4的齐次变换矩阵**来表示。这种4*4矩阵一方面描述了旋转（3x3的旋转子块），另一方面描述了平移（最后一列前三个元素）。形式为：

```
[ R（3×3旋转矩阵）   t（3×1平移） ]
[     0  0  0             1      ]
```

这样的齐次矩阵可以同时处理空间中的旋转和平移，非常适合用来级联描述各个关节变换。在运动学里，DH参数定义每段连杆的几何关系——通过这些参数可以构造出每一节的4*4齐次矩阵。FK（正运动学）问题，就是把 n 个这样的4*4变换矩阵顺次连乘，求出末端的整体变换。n 个关节就是 n 次矩阵乘法，复杂度 O(n)。**FK 没有多解问题**——关节角确定了，末端位姿唯一确定。

工程应用时要特别注意三点：

1. **DH参数必须和URDF、真机标定一致**，否则FK解算和实际有偏差；
2. **姿态（空间方向）内部建议用四元数或旋转矩阵表示**。这样可以避免**欧拉角常见的“万向节锁”（Gimbal Lock）问题**。
  - **四元数**是一种四维向量，可以无奇异地表示三维旋转，数值上也更稳定。  
  - **旋转矩阵**直接用3x3正交矩阵表达旋转，同样不受万向节锁约束。  
  - **欧拉角**虽然直观（比如以roll-pitch-yaw三个转角描述空间姿态），但当两个旋转轴重合时会丢失一个自由度，导致“万向节锁”：即某些方向无法独立转动，系统会失去运动自由度。  
   所以**推荐内部用四元数/旋转矩阵存储和运算，欧拉角仅用于人机界面展示**。
3. **FK不只服务于「算末端在哪」**，IK 求逆、碰撞检测时每个link的姿态、Jacobian矩阵、重力项G(q)等都要用到FK。



### 核心公式

```
T_{i-1}^{i} = Rot_z(θ_i) · Trans_z(d_i) · Trans_x(a_i) · Rot_x(α_i)   // Modified DH
T_base^tcp = T_0^1 · T_1^2 · … · T_{n-1}^n · T_tool
```



### 详细流程

```
输入：q[1..n]，DH 表，T_tool
Step 1  T ← I₄
Step 2  for i=1..n：查 (a,α,d,θ_offset)，θ=qi+offset，T ← T · dh(i)
Step 3  T ← T · T_tool
Step 4  提取 (x,y,z) + 姿态（优先四元数/旋转矩阵，欧拉角仅显示）
输出：T_base^tcp
```



### 方法对比


| 实现            | 复杂度  | 优点             | 缺点    |
| ------------- | ---- | -------------- | ----- |
| 迭代连乘          | O(n) | 简单通用           | —     |
| 递归树           | O(n) | 适合分支臂          | 代码稍复杂 |
| 中间缓存          | 均摊更低 | 只动部分关节时快       | 需维护状态 |
| KDL/Pinocchio | O(n) | 与 URDF 一致、顺带 J | 依赖库   |




### 常见坑


| 坑           | 原因                      | 处理                  |
| ----------- | ----------------------- | ------------------- |
| FK 与真机偏差    | DH 标定、齿隙、半闭环            | 交叉验证 Pinocchio；实测标定 |
| DH/URDF 不一致 | Standard vs Modified 混用 | 全链路统一约定             |
| 姿态跳变        | 欧拉角表示                   | 内部四元数，slerp 插值      |




### 面试快答

- **FK vs IK：** FK 唯一解；IK 可能无解/多解/不收敛  
- **复杂度：** n 关节 O(n)  
- **用途：** IK 验证、碰撞 FK、Jacobian、G(q)、视觉 TF 链

## 1.2 逆运动学 IK — 全解法详解



### 一句话定义

已知末端目标位姿 `T_d`，求关节角 `q`。**欠定（冗余臂）或过定（一般非线性）→ 核心难点在多解、奇异、收敛。**

### 口述描述（总述）

逆运动学和 FK 反过来：**「末端要到某个位置和姿态，各关节应该转多少？」** 这是机械臂里最常考、也最难的一块。

难点在于：6 自由度机械臂对一个 6D 位姿任务刚好确定，但可能有**多组解**（肘上/肘下、腕部翻转）；7 自由度臂则**多 1 个冗余**，同一末端位姿有无穷多解；目标不可达时**无解**；靠近奇异点时数值解法**不收敛**。

所以工程上不会只用一种方法，而是按场景组合：**结构满足 Pieper 条件（腕部三轴交一点）的 6DOF 臂，优先用解析几何法，微秒级、可枚举全部解；7DOF 冗余臂用臂角法，固定冗余参数（比如 q4）降成 6DOF 再解；通用 fallback 用 DLS 或 LM 数值迭代；有避障、限位等复杂约束时上优化 IK；MoveIt 里则常用 KDL LMA 或 Trac-IK 做规划管线的 IK 插件。** 生产级方案是「自研解析主路径 + 库 fallback + 失败上报换 seed/放宽约束」。

### 解法总览（必背表）


| 类别          | 代表                 | 速度   | 通用性     | 多解     | 约束支持  |
| ----------- | ------------------ | ---- | ------- | ------ | ----- |
| 解析几何        | Pieper 6DOF        | μs   | 结构受限    | 显式枚举   | 限位筛选  |
| 臂角法         | 7DOF 固定 ψ/q4       | μs   | 7DOF 定制 | 参数化一族  | 臂角策略  |
| Jacobian 伪逆 | 一阶线性化              | ms   | 通用      | 靠 seed | 弱     |
| DLS 阻尼最小二乘  | 奇异鲁棒               | ms   | 通用      | 靠 seed | 弱     |
| LM          | 非线性最小二乘            | ms   | 通用      | 靠 seed | 弱     |
| 优化 IK       | IPOPT/NLopt/CasADi | ms–s | 通用      | 代价函数   | **强** |
| 库           | KDL LMA, Trac-IK   | ms   | 通用      | 多 seed | 中     |




### 选型决策树

```
后三轴交于一点（Pieper）？
  ├─ 是 → 解析 IK 主路径
  └─ 否 → 7DOF？
         ├─ 是 → 臂角法 / 固定冗余角 / 零空间
         └─ 否 → DLS/LM + 多 seed → 仍失败 → 优化 IK
```

### 解法 1：解析几何法（6DOF Pieper 型）

**适用条件：** 6 关节，后 3 轴（腕部）轴线交于一点 → 位置与姿态解耦。

**口述描述：**

解析 IK 的核心思路是**把「末端到哪」和「末端朝哪」拆开解**。前提是腕部三根轴交于一点（球腕），这样肩肘三个关节主要决定「腕心在哪」，腕部三个关节主要决定「手掌朝哪」。

具体做法是：先从目标位姿里去掉工具偏移，得到腕部中心应该在的位置——相当于从 TCP 沿末端 z 轴往回退一段 d6。腕心位置定了以后，q1 用 atan2 就能解出来（绕竖直轴转多少够到那个 XY 方向）；然后在肩-肘-腕构成的竖平面里，用连杆长度和余弦定理解 q2、q3，这里通常有**肘上、肘下两组解**。肩肘定下来之后，用 FK 算出前三轴的旋转矩阵，用目标姿态减掉这部分，剩下就是腕部三根轴要完成的旋转，做 ZYZ 欧拉分解得到 q4、q5、q6。

最后把所有合法解（最多 8 组）列出来，**按关节限位过滤，再选与上一帧关节角最接近的那组**，保证轨迹连续。这种方法极快、确定性强，是工业 6DOF 臂实时控制的首选，但构型必须满足 Pieper 条件，换一种臂就要重新推公式。

**详细流程：**

```
输入：T_target = [R_d | p_d]，T_tool，seed q_prev
Step 1  剥离工具：T_w = T_target · inv(T_tool)
Step 2  腕心：p_w = p_d - d6 · R_d · ẑ
Step 3  肩关节：q1 = atan2(p_w.y, p_w.x)
Step 4  肩肘平面（余弦定理）：
        - 已知肩 S、腕 W、连杆长 l2,l3 → 解 q2,q3
        - 两解：肘上 / 肘下
Step 5  腕部旋转：R_0³ = FK_rot(q1,q2,q3)
        R_3⁶ = inv(R_0³) · R_d
Step 6  ZYZ/Euler 分解 R_3⁶ → q4,q5,q6
        注意 q5≈0 万向节锁 → q4+q6 耦合
Step 7  枚举最多 8 组解 → 筛：限位内、‖q-q_prev‖最小、远离奇异
输出：q_best 或 NO_SOLUTION
```

**优劣：**


| 优点                 | 缺点          |
| ------------------ | ----------- |
| 极快（μs）、确定性、可枚举全部解  | 仅适用特定构型（球腕） |
| 实时控制首选             | 构型变需重新推导    |
| 解可预测、连续性好（配合 seed） | 腕部奇异需特殊处理   |


**适用：** 6DOF 工业臂（UR、ABB 等球腕）、实时笛卡尔伺服。

### 解法 2：臂角法（7DOF 冗余臂）

**核心思想：** 7 关节对 6D 位姿多 1 自由度 → 固定冗余参数（臂角 ψ 或关节 q4）→ 降为 6DOF 确定问题。

**臂角 ψ 物理含义：** 肩-肘-腕 构成的臂平面，绕「肩-腕连线」旋转的角度。

**口述描述：**

7 自由度机械臂对 6D 位姿任务是**冗余**的：末端位置和姿态共 6 个约束，却有 7 个关节，多出来的 1 自由度意味着**同一个 TCP 位姿，肘部可以抬高或压低**，这叫自运动。如果不额外指定这 1 维，IK 有无穷多解，没法直接用于控制。

臂角法的做法是：**先人为固定冗余自由度**，最常见的是固定第 4 关节 q4（肘关节角），或固定臂角 ψ（肩-肘-腕平面绕肩-腕轴的旋转角）。固定之后，问题从 7 方程 7 未知数变成确定的 6DOF 问题，就可以用类似 6DOF 解析几何那套去解 q1、q2、q3 和 q5、q6、q7。

工程上 q4 通常取**上一帧的值**以保持连续，或者按任务需要调整——比如避障时抬高肘部、紧凑操作时压低。解完后用 FK 回代验证误差，如果超限或不可达，就在 q4 附近小步搜索（比如 ±5°），还不行就 fallback 到数值 IK。我在 7DOF 蓝思臂项目里就是这套：**自研臂角法做主路径，μs 级延迟，多解策略可控；Trac-IK 做 fallback。**

**详细流程（固定 q4 工程版）：**

```
输入：T_target，q4_ref（上一帧/任务指定），seed
Step 1  固定 q4 = q4_ref
Step 2  用几何法求肩-腕位置 → q1,q2,q3（在含 q4 的平面内）
Step 3  腕部旋转分解 → q5,q6,q7
Step 4  FK 回代验证 ‖T_ee - T_d‖ < ε
Step 5  限位检查；失败则 q4 ± Δq4 搜索（如 ±5° 步进）
Step 6  选 ‖q - q_prev‖ 最小解
输出：q 或 fallback 数值 IK
```

**优劣：**


| 优点                | 缺点         |
| ----------------- | ---------- |
| 快、可复现、适合 7DOF 实时环 | 需针对构型推导    |
| 冗余可控（肘部抬高/压低）     | q4 选不好可能无解 |
| 与项目（蓝思 7DOF）直接对应  | 非标准构型需重写   |


**适用：** Franka、KUKA iiwa、自研 7DOF 臂；折纸/避障时调 q4 抬肘。

### 解法 3：Jacobian 迭代法（数值 IK）

**核心思想：** 在当前 q 处线性化 `Δx ≈ J(q)·Δq`，迭代修正直至收敛。

**口述描述：**

数值 IK 的思路是**迭代逼近**：从一组初始关节角 q0 出发（通常是上一帧），先用 FK 算当前末端位姿，和目标比一下误差 Δx；如果误差足够小就成功；否则在当前 q 处算 Jacobian 矩阵 J，它描述「每个关节动一点，末端动多少」；然后解 Δq = J⁺Δx，让关节沿能减小误差的方向走一小步；更新 q，重复直到收敛或超过最大迭代次数。

姿态误差**不能**用欧拉角直接相减，而要把旋转矩阵差转成轴角或旋量。数值法的优点是**任意构型都能用**，缺点是 ms 级慢、**不保证收敛**，在奇异点附近 Jacobian 伪逆会爆炸。所以实际很少单独用纯伪逆，而是配合 DLS 阻尼，或者直接用 LM 算法。

**详细流程（单步）：**

```
输入：x_d（6D：3pos+3ori），q_init，α步长，K_max，ε
for k = 0..K_max:
  Step 1  x_k ← FK(q_k)                    // 正解
  Step 2  Δx ← x_d ⊖ x_k                   // 位姿误差（见下）
  Step 3  if ‖Δx‖ < ε: return q_k
  Step 4  J ← Jacobian(q_k)                // 6×n
  Step 5  Δq ← α · J⁺ · Δx                 // 伪逆（见解法4 DLS）
  Step 6  q_{k+1} ← q_k + Δq；clip 限位
return FAIL
```

**姿态误差（重要）：** 不用欧拉角相减。用 `ΔR = R_d · R_k^T` → 旋量/轴角 3 维。

**优劣：**


| 优点             | 缺点             |
| -------------- | -------------- |
| 任意构型通用         | ms 级，不保证收敛     |
| 实现简单           | 奇异附近 J⁺ 爆炸     |
| 可热启动（上一帧 seed） | 多解依赖 seed，可能跳解 |

### 解法 4：DLS（阻尼最小二乘）

**口述描述：**

DLS 是数值 IK 里**专门对付奇异点**的改进。普通伪逆在奇异构型附近，JJᵀ 接近奇异，J⁺ 的元素会非常大，算出的 Δq 会猛跳，关节速度爆炸。DLS 在 JJᵀ 上加一个 λ²I 的正则项，保证矩阵始终可逆，相当于在「快速逼近目标」和「步子别太大」之间折中。λ 大时更像梯度下降，慢但稳；λ 小时接近伪逆，快但在奇异附近仍要小心。MoveIt 和 Trac-IK 内部常用这类稳健化策略。

**公式：** `Δq = Jᵀ (J Jᵀ + λ²I)⁻¹ Δx`

**与伪逆区别：**


|     | 伪逆 J⁺ | DLS                |
| --- | ----- | ------------------ |
| 奇异处 | 范数→∞  | λ²I 保证可逆           |
| λ 大 | —     | 退化为梯度下降，慢但稳        |
| λ 小 | 接近伪逆  | 快但近奇异不稳定           |
| 调参  | 无     | λ 常取 0.01~0.1 或自适应 |


**详细流程：** 同解法 3，Step 5 换 DLS 公式。

**适用：** 通用 fallback、奇异附近、MoveIt 内部备选。

---



### 解法 5：Levenberg-Marquardt（LM）

**口述描述：**

LM 可以看成在 Gauss-Newton（快但奇异处不稳定）和梯度下降（慢但稳）之间**自动切换**的算法。每次迭代看误差有没有下降：下降了就把阻尼 λ 减小，更激进地逼近；没下降就增大 λ，退化成小步梯度下降。KDL 的 LMA IK 和 Trac-IK 内部都用这类方法，比手写 Jacobian 伪逆循环更鲁棒，是通用 fallback 的常见选择。

**思想：** 在 Gauss-Newton 与梯度下降间自适应插值。

```
Δq = (JᵀJ + λ·diag(JᵀJ))⁻¹ Jᵀ Δx
误差下降 → λ 减小（更像 GN，快）
误差上升 → λ 增大（更像梯度，稳）
```

**优劣：** 比 DLS 收敛更鲁棒；比解析慢；KDL LMA、Trac-IK 内部常用。

---



### 解法 6：优化 IK

**口述描述：**

当约束变复杂——不仅要到达位姿，还要**避障、严格限位、冗余关节偏好某一姿态**——解析和简单数值 IK 就不够用了。优化 IK 把问题建成一个**带约束的非线性优化**：代价函数里写位姿误差、正则项（比如尽量靠近 home 姿态），约束里写关节上下限、碰撞距离大于安全阈值等，然后用 IPOPT、NLopt 或 CasADi 求最优 q。

优点是**约束表达力最强**，7DOF 冗余可以自然通过正则项选解；缺点是慢（毫秒到秒级），可能陷入局部最优，需要好的 seed。适合离线规划、抓取避障、或者作为 arm-angle 失败后的最后一道 fallback。

**问题建模：**

```
minimize  w_p‖p_ee - p_d‖² + w_R‖log(R_d^T R_ee)‖² + w_reg‖q - q_ref‖²
subject to  q_min ≤ q ≤ q_max
          d_collision(q) ≥ d_safe    // 可选
          自定义等式/不等式
```

**详细流程：**

```
Step 1  定义代价（位姿 + 正则 + 冗余偏好）
Step 2  约束（限位 box、碰撞 signed distance）
Step 3  q0 ← seed（上一帧/home/解析粗解）
Step 4  IPOPT / NLopt / CasADi 求解
Step 5  FK 验证；失败则换 seed 或放宽约束
```

**优劣：**


| 优点            | 缺点       |
| ------------- | -------- |
| 约束强（避障、限位、冗余） | 最慢（ms~s） |
| 统一框架          | 需调权重 w   |
| 冗余自动选解        | 局部最优     |


**适用：** 抓取避障、7DOF 零空间优化、离线规划。

---



### 解法 7：库封装（KDL / Trac-IK / MoveIt）

**口述描述：**

实际项目里很少从零写数值 IK，而是用成熟库。KDL LMA 是 MoveIt 内置的备选 IK 求解器；Trac-IK 同时跑 NLopt 和 KDL，**多 seed 并行**，成功率比单 KDL 高；MoveIt 的 `/compute_ik` Service 把 IK 封装成规划管线的一环，笛卡尔目标自动转关节 goal。

我的分工是：**实时控制环用自研臂角法**（延迟和选解策略可控），**MoveIt 规划层走插件 IK**，**交叉验证和 fallback 用 Pinocchio/Trac-IK**。这样既不用重复造轮子，又不在实时路径上被库的 ms 延迟绑死。


| 库         | 内部算法           | 特点            | 用法            |
| --------- | -------------- | ------------- | ------------- |
| KDL LMA   | LM             | MoveIt 默认备选   | `/compute_ik` |
| Trac-IK   | NLopt + KDL 并行 | 成功率高、多 seed   | 替换 IK 插件      |
| MoveIt IK | 插件式            | 笛卡尔 goal → 关节 | 规划管线          |
| Pinocchio | 可自写优化          | 与动力学统一        | 验证/优化 IK      |


**生产级组合（你的项目话术）：**

```
主：自研臂角法（μs，7DOF 定制）
  ↓ 失败
Fallback1：Trac-IK / KDL LMA（多 seed）
  ↓ 失败
Fallback2：优化 IK（复杂约束）
  ↓ 失败
NO_IK_SOLUTION → 换目标/放宽姿态/关节空间绕路
```



### IK 失败处理


| 现象             | 原因        | 处理                      |
| -------------- | --------- | ----------------------- |
| NO_IK_SOLUTION | 超出工作空间    | 换 seed、放宽姿态（只约束位置）      |
| 跳解             | seed 差/多解 | 上一帧 seed、min ‖q-q_prev‖ |
| 不收敛            | 奇异/步长大    | DLS 增大 λ、减小 α           |
| 限位外            | 目标不可达     | 投影到限位或换目标               |




### 面试快答

- **几种 IK？** 解析、臂角、Jacobian/DLS/LM、优化、库 — 按速度/通用性/约束选型  
- **7DOF 为何臂角法？** 多 1 自由度，须固定 ψ 或 q4 才确定  
- **DLS 为何比伪逆好？** 奇异处 JJᵀ 奇异，加 λ²I 稳定  
- **为何自研+库？** 定制延迟与多解策略 + 库做 fallback 验证

## 1.3 雅可比 · 奇异 · 零空间



### 口述描述（总述）

这三个概念是一条线上的：**Jacobian 描述关节速度和末端速度的关系；奇异点是这种映射退化的地方；零空间是冗余臂在不影响末端任务的前提下还能「多动」的那部分自由度。**

面试里常连环问：「末端速度和关节速度什么关系？」→「什么时候会奇异？」→「7DOF 冗余怎么用？」——可以按这个顺序答。

### 雅可比

**口述描述：**

Jacobian 矩阵 J 把关节速度映射到末端速度：ẋ = J(q)·q̇。末端 ẋ 是 6 维（3 个线速度 + 3 个角速度），J 是 6×n。几何上，J 的第 i 列表示「只有第 i 关节在转、其他不动时，末端线速度和角速度各是多少」，由该关节轴方向和末端相对位置叉乘得到。

反过来，给定想要的末端速度 ẋ，求 q̇ 是欠定或超定问题，常用伪逆、DLS 或 QP（带关节限速约束）。IK 的数值迭代、笛卡尔空间轨迹跟踪、力控里的速度映射都依赖 J。

**定义：** `ẋ = J(q) q̇`，`ẋ` 6D（线速度+角速度），`J` 6×n。

**几何 Jacobian 求法（递推）：**

```
J = [J_v; J_ω]
J_v 第 i 列 = z_{i-1} × (p_ee - p_{i-1})   // 旋转关节
J_ω 第 i 列 = z_{i-1}
```

**逆速度映射：**


| 方法  | 公式                      | 特点    |
| --- | ----------------------- | ----- |
| 伪逆  | q̇ = J⁺ ẋ               | 奇异不稳定 |
| DLS | q̇ = Jᵀ(JJᵀ+λ²I)⁻¹ẋ     | 稳健    |
| QP  | min ‖q̇‖ s.t. Jq̇=ẋ, 限位 | 工业常用  |


---



### 奇异点

**口述描述：**

奇异点的本质是：**在某个构型下，Jacobian 降秩了**，末端在某个方向上的速度无法通过关节运动产生——或者说，需要无穷大的关节速度才能产生有限的末端速度。数学上 det(JJᵀ) 趋近 0。

常见三类：一是**腕部奇异**，第 5 轴接近 0 时，第 4 和第 6 轴会耦合，绕同一轴转；二是**肩部奇异**，腕心落在肩轴上，手臂完全伸直或折叠；三是**工作空间边界**，再往外够不着了。工程上用可操作度 w = √det(JJᵀ) 监控，低于阈值就降速、改冗余角或换关节空间路径。MoveIt 的 computeCartesianPath 走到 singular 处常会 fraction < 1 中断。

**本质：** `det(JJᵀ) → 0`，某笛卡尔方向瞬时不可控。

**三类：**


| 类型   | 构型     | 表现       |
| ---- | ------ | -------- |
| 腕部奇异 | q5≈0   | q4/q6 耦合 |
| 肩部奇异 | 腕心在肩轴上 | 臂完全伸直/折叠 |
| 边界奇异 | 工作空间边缘 | 可达性丧失    |


**检测：** 可操作度 `w = √det(JJᵀ)`；条件数 `cond(J)`。

**规避流程：**

```
Step 1  监控 w(q) < w_thresh
Step 2  降速 / 改冗余角 q4 / 改路径绕开
Step 3  DLS 增大 λ
Step 4  笛卡尔路径 fraction 中断 → 换关节空间
```

---



### 零空间（冗余臂）

**口述描述：**

7DOF 臂的 J 是 6×7，有多余的一维。零空间投影 N = I - J⁺J 的作用是：**找一组关节速度，送进 N·z 后，末端完全不动**。于是可以把控制写成 q̇ = J⁺ẋ + N·z：第一项完成末端任务，第二项在零空间里做优化——比如让 q 尽量靠近上一帧（解连续）、远离关节限位、或躲开障碍物。

这是冗余臂区别于 6DOF 的核心工具，和臂角法互补：臂角法是「先固定冗余参数再解析解」，零空间法是「速度级实时优化冗余」。

**投影：** `N = I - J⁺J`

**冗余控制：**

```
q̇ = J⁺ ẋ + N · z
z = -k ∇H(q)   // H：避障、min‖q-q_prev‖、远离限位
```

**特点：** 主任务与零空间解耦；7DOF 核心工具。

### 面试快答

- **奇异原因：** JJᵀ 奇异 → 某方向速度无法产生  
- **computeCartesianPath fraction<1：** 常因 IK 失败或奇异  
- **零空间用途：** 冗余优化不影响末端任务

## 2.1 路径 vs 轨迹 · 关节 vs 笛卡尔规划



### 口述描述

很多人会把「路径规划」和「轨迹规划」混为一谈，面试里最好先**切开讲**：

**路径（Path）** 只有几何形状，回答「从 A 到 B 经过哪些点」，但没有「什么时候到哪」。MoveIt 里 OMPL 采样出来的就是一条关节空间折线，还没有时间信息。

**轨迹（Trajectory）** 在路径基础上加了时间参数化，回答「每一时刻关节角、速度、加速度是多少」，输出才是带 time_from_start 的 JointTrajectory，控制器才能跟踪。

至于**在关节空间规划还是笛卡尔空间规划**：回 home、大范围绕障适合关节空间，因为采样快、没有笛卡尔奇异；抓取接近、装配插入适合笛卡尔直线，因为你要控制的是「手走一条直线」，而不是「关节走一条漂亮的曲线」。实际项目常常组合：长距离关节空间 OMPL 规划，最后一段 computeCartesianPath 直线接近。

### 概念


| 概念                  | 含时间？ | 输出                 | 例子                                |
| ------------------- | ---- | ------------------ | --------------------------------- |
| **Path 路径**         | 否    | 几何 waypoints       | 关节角序列 q_i                         |
| **Trajectory 轨迹**   | 是    | q(t), q̇(t), q̈(t) | JointTrajectory 带 time_from_start |
| **Motion Planning** | —    | 避障 + path + 时间参数化  | MoveIt 全流程                        |




### 规划空间选型


| 场景         | 选            | 原因           |
| ---------- | ------------ | ------------ |
| 回 home、大范围 | 关节空间         | 快、无奇异、RRT 高效 |
| 抓取接近、插入    | 笛卡尔直线        | 末端路径可控       |
| 绕障         | 关节 + OMPL    | 采样在关节空间      |
| 精细装配       | 笛卡尔 + 小 step | 路径精度         |

## 2.2 MoveIt2 完整流程



### 口述描述

MoveIt2 不是单纯的 IK 接口，而是一套**从「想去哪」到「怎么无碰撞地过去、再按时间执行」**的完整框架。可以按三层理解：

**配置层：** URDF 描述机器人物理结构，SRDF 用 Setup Assistant 生成，定义 Planning Group（哪些关节参与规划）、ACM 自碰撞忽略表（相邻连杆碰撞体重叠的不检）、命名姿态 home/ready 等。这一步做错，后面规划和碰撞全错。

**规划层：** move_group 节点收到目标（关节角或笛卡尔位姿），笛卡尔目标先走 IK 转成关节 goal，然后 Planning Pipeline 调用 OMPL 等在关节空间采样找无碰撞路径，每个采样点通过 StateValidityChecker 做 FK + FCL 碰撞检测；找到路径后 shortcut 简化，再 IPTP/TOTG 时间参数化，得到 JointTrajectory。

**执行层：** trajectory_execution_manager 通过 FollowJointTrajectory Action 发给 ros2_control 或自研 SDK。MoveIt 默认 10Hz 左右出稀疏点，**真正 500Hz–1kHz 跟踪靠执行层插值**。

### 架构

```
URDF + SRDF（Planning Group, ACM）
Planning Scene（机器人 + 障碍）
move_group → Planning Pipeline → 执行
```



### SRDF 生成（Setup Assistant）

```
Load URDF → Self-Collisions(ACM) → Planning Groups
→ Robot Poses → End Effectors → Generate
```



### plan() 七步详解

```
Step 1  MotionPlanRequest：start(/joint_states), goal(IK或关节), group, planner_id
Step 2  Planning Pipeline 调 OMPL/CHOMP/Pilz
Step 3  OMPL 关节空间采样；StateValidityChecker → FK + FCL
Step 4  几何 path（无时间）
Step 5  shortcut 简化
Step 6  IPTP/TOTG 时间参数化
Step 7  JointTrajectory → FollowJointTrajectory → controller
```

## 2.3 OMPL 采样规划器详解



### 口述描述

OMPL 是 MoveIt 默认的路径搜索库，工作在**关节空间**。它本身不懂机器人，只负责「在一个高维空间里找一条从起点到终点的通路」，至于某个点是否合法，要问 MoveIt 的碰撞检测回调。

**RRTConnect** 是工程上最常用的：从起点和终点各长一棵树，随机采样扩展，两棵树碰头就连起来。比单树 RRT 快很多，MoveIt 默认就是它。**RRT** 在 RRT 基础上做 rewiring，路径渐近最优但慢。**PRM** 适合同一环境反复查询，先建路图再搜索。**CHOMP/STOMP** 不是纯采样，而是拿一条初始路径做梯度/随机优化拉平滑，适合码垛等重复轨迹。

面试关键点：**OMPL 不做碰撞**，碰撞是 MoveIt 在每次采样时调 FCL 做的；规划阶段检完认为无碰撞的路径，执行时默认信任，环境变了要 replan。


| 算法             | 流程要点                 | 优点       | 缺点       | 场景      |
| -------------- | -------------------- | -------- | -------- | ------- |
| **RRT**        | 单树随机扩展               | 简单       | 慢、路径糙    | 教学      |
| **RRTConnect** | 双向 RRT，start/goal 两树 | **默认，快** | 非最优      | 通用 Demo |
| **RRT**        | 采样+rewiring          | 渐近最优     | 慢        | 路径质量    |
| **PRM**        | 先建路图再查询              | 重复查询快    | 首建慢      | 固定工位    |
| **CHOMP**      | 梯度优化已有 path          | 平滑       | 需初值、易陷局部 | 码垛      |
| **Pilz**       | 工业速度规划               | 节拍严格     | 配置复杂     | 产线      |


**RRTConnect 流程：**

```
树 A 从 start，树 B 从 goal
loop:
  q_rand ← random()
  q_near ← nearest(树A, q_rand)
  q_new ← extend(q_near → q_rand)  // 每步碰撞检测
  if 碰撞: continue
  树A.add(q_new)
  if distance(树A, 树B) < ε: 连接 → 成功
  交换 A/B
```

## 2.4 碰撞检测原理



### 口述描述

MoveIt 的碰撞检测回答一个问题：**「在当前关节角 q 下，机器人有没有碰到自己或环境？」** 实现上靠 FCL 做几何碰撞，不是力控里的「接触力检测」。

流程是：给定 q，先 FK 算出每个 link 在空间中的位姿，把 URDF 里的 collision 几何（box/cylinder/mesh）变换过去；同时 Planning Scene 里还有环境的 CollisionObject、Octomap 体素等障碍。FCL 先做宽相位（AABB/BVH 粗筛），再做窄相位（GJK/EPA 精确算穿透或距离）。自碰撞检测时，SRDF 里的 ACM 会跳过相邻连杆等永远不需要检的对，加速检测。

**关键区分：** 这是**规划时**的几何检测——OMPL 每采一个点、每插值一段路径都要检，一次 plan 可能上万次；不是执行时每毫秒都在做实时避障。执行中若环境变化，要靠 scene monitor 触发 stop 或 replan；毫秒级反应式避障要上 cuMotion 这类 GPU 规划器。

**关键：OMPL 不做碰撞，MoveIt + FCL 做。**

```
采样 q → FK → 各 link 位姿
→ FCL 宽相位(AABB/BVH) → 窄相位(GJK/EPA)
→ 自碰撞(减ACM) + 环境障碍
→ free / collision
```


| 维度  | 说明                  |
| --- | ------------------- |
| 类型  | 几何穿透，非力控            |
| 时机  | 规划时每个 state + 路径插值点 |
| 执行  | 默认信任轨迹；变化需 replan   |


**Planning Scene：** RobotState + CollisionObject + Octomap + ACM。

## 2.5 笛卡尔路径 computeCartesianPath



### 口述描述

computeCartesianPath 解决的是：**「我想让 TCP 走一条空间直线（或经过几个笛卡尔路点），关节角怎么配？」** 它不是 OMPL 那种全局规划，而是**局部直线插补**。

做法是：在起点和终点位姿之间，按 step_size（比如 1cm）插出一串中间末端位姿；每个中间点对当前 q 做 IK，再碰撞检测；如果某一步 IK 失败、碰了、或者关节角相对上一步跳变超过 jump_threshold（说明 IK 换解支了），就停。最后返回 fraction = 实际走完的比例。fraction < 1 非常常见，原因可能是奇异、IK 无解、碰撞或 step 太大。

抓取项目里典型用法：**长距离用关节空间 OMPL 规划到 grasp pre-pose 附近，最后 5–10cm 用 computeCartesianPath 直线接近**，保证入刀方向。

**流程：**

```
for 每个笛卡尔步长 step_size:
  插值末端位姿 p_i
  IK(p_i) → q_i
  碰撞检测(q_i)
  if ‖q_i - q_{i-1}‖ > jump_threshold: break  // 防 IK 跳解
fraction = 成功步数 / 总步数
```

**fraction < 1 原因：** IK 失败、奇异、碰撞、step 过大。

---



## 2.6 时间参数化 · 规划失败排查



### 口述描述

OMPL 输出的路径只有一串关节角 waypoints，**没有时间戳**，机器人不能直接执行——不知道每个点该多快到。时间参数化的任务就是在满足各关节**最大速度、最大加速度**（来自 URDF 或 yaml）的前提下，给每个点分配 time_from_start，有时还附带 q̇、q̈。

MoveIt 默认常用 IPTP（迭代抛物线时间参数化），工业场景也常用 TOTG 追求时间最优，Pilz 插件适合要严格节拍的产线。输入是几何 path + 限速，输出才是 controller 能吃的 JointTrajectory。

**规划失败排查**可以按 error code 分：NO_IK_SOLUTION 换 seed 或放宽姿态；COLLISION 简化障碍或调 ACM；TIMEOUT 增大 allowed_planning_time 或换 RRT*；computeCartesianPath fraction<1 则减小 step、加中间路点、避奇异。面试时讲一个你实际遇到的 case 会加分。

### 时间参数化


| 方法   | 特点              |
| ---- | --------------- |
| IPTP | MoveIt 默认，迭代抛物线 |
| TOTG | 时间最优            |
| Pilz | 工业节拍            |


输入：path waypoints + 关节 v/a 限制 → 输出带 time_from_start 的 trajectory。

### 失败排查决策树

```
规划失败？
├─ NO_IK → 换 seed、放宽姿态、关节目标
├─ COLLISION → 简化障碍、ACM、换 RRT*
├─ TIMEOUT → 增 allowed_planning_time
└─ fraction<1 → 减小 step、加中间点、避奇异
```

## 2.7 SDK 执行层 · ROS2 集成



### 口述描述

MoveIt 和执行层之间有一道**频率鸿沟**：MoveIt 规划可能 10–100Hz 出一串稀疏 waypoints，但伺服驱动器通常要 500Hz–1kHz 的位置指令才能平滑跟踪。SDK 执行层的职责就是**插值 + 限位 + 安全**：收到 JointTrajectory 或上层 setJointPosition，在相邻 waypoints 之间做样条或线性插值，以 500Hz–1kHz 下发；同时做关节限位裁剪、通信超时、异常降级。

ROS2 集成上：/joint_states 是 Topic 持续发布当前关节角；/compute_ik 是 Service 做单次 IK；move_group 和 FollowJointTrajectory 是 Action，适合几秒到几十秒的长轨迹，带 feedback 和 cancel。TF 树维护 base→link→tool→camera 的坐标关系，查询时要带 timestamp，因为机器人在动。

**为何 10Hz 规划、500Hz 控制仍能工作？** 因为规划只负责「路怎么走」，执行层负责「每 2ms 发一个中间点」，两层分工明确。

### 执行流程

```
MoveIt 10Hz 稀疏 waypoints
  ↓ 500Hz–1kHz 样条/线性插值
  ↓ setJointPosition / FollowJointTrajectory
  ↓ 驱动器 PID（1kHz 内环）
```



### ROS2 选型


| 类型      | 接口                                 | 场景    |
| ------- | ---------------------------------- | ----- |
| Topic   | /joint_states                      | 状态流   |
| Service | /compute_ik                        | 单次 IK |
| Action  | /move_group, FollowJointTrajectory | 长轨迹   |


**TF：** `base → link → tool → camera`；查询带 timestamp。

### 面试快答

- **为何 10Hz 规划 500Hz 控制？** 规划出稀疏点，执行层插值跟踪  
- **OMPL 碰撞何时做？** 规划采样时，非执行力控检测

## 3.1 控制链：PID → CTC → 阻抗/导纳/力位混合



### 口述描述（总述）

机械臂控制可以按「越来越懂物理模型」来理解：**PID 只盯着误差闭环；CTC 用动力学模型做前馈；阻抗/导纳/力位混合则进入「和环境怎么交互」的层面。**

数据流上：上层给 desired 轨迹 → 控制律算 τ → 驱动器电流环执行。运动学告诉你 q_d 是多少，动力学告诉你「要产生 q̈ 需要多少 τ」，控制律把两者合起来。

### 3.1.1 关节 PID

**口述描述：**

最基础的位置控制：每个周期读当前关节角 q，和目标 q_d 做差 e，用 PID 算出要施加的力矩（或电压）。Kp 像弹簧刚度，越大跟得越紧但容易振荡；Ki 消长期偏差，但要防积分饱和；Kd 提供阻尼。如果有重力补偿或摩擦前馈 τ_ff，叠加上去可以减轻 PID 负担——我在 SDK 里做的就是 G(q) 前馈 + 模组自带位置 PID。

```
τ = Kp·e + Ki·∫e + Kd·ė + τ_ff,   e = q_d - q
```


| 项    | 作用       | 过大后果   |
| ---- | -------- | ------ |
| Kp   | 刚度       | 振荡     |
| Ki   | 消稳态      | windup |
| Kd   | 阻尼       | 噪声放大   |
| τ_ff | 前馈 G/M/C | 减反馈负担  |


**流程：** 设 q_d → 读 q → 算 e → PID → τ → 电流环。

---



### 3.1.2 计算力矩控制 CTC

**口述描述：**

CTC 的核心思想是：**既然动力学方程 τ = Mq̈ + Cq̇ + G 告诉我们要产生期望运动需要多少力矩，那就先算好这个前馈 τ_ff，PD 只负责补偿模型误差。**

每个控制周期：轨迹发生器给出 q_d、q̇_d、q̈_d；用 Pinocchio 或 RNE 根据当前 q、q̇ 算 M、C、G；τ_ff = M q̈_d + C q̇_d + G；再算 e = q_d - q，τ_fb = Kp e + Kd ė；总力矩 τ = τ_ff + τ_fb 下发。模型越准，PD 越轻松，高速重载跟踪越好。参数不准时前馈会有误差，靠 PD 兜底，但增益要调大，这就是为什么要做动力学辨识。

**你的边界（诚实）：** 已做 G(q) 前馈；全 M/C CTC 需辨识后上线。

```
τ = M(q)q̈_d + C(q,q̇)q̇_d + G(q) + Kp·e + Kd·ė
```

**流程：**

```
Step 1  轨迹给出 q_d, q̇_d, q̈_d
Step 2  Pinocchio/RNE 算 M,C,G
Step 3  τ_ff = M q̈_d + C q̇_d + G
Step 4  τ_fb = Kp e + Kd ė
Step 5  τ = τ_ff + τ_fb → 电机
```

**优劣：**


| 优点           | 缺点           |
| ------------ | ------------ |
| 跟踪精度高（模型准）   | 依赖辨识精度       |
| 物理意义清晰       | 实现复杂         |
| 重载/高速优于纯 PID | 参数不准时 PD 压力大 |


---



### 3.1.3 阻抗 vs 导纳

**口述描述：**

接触任务（装配、打磨、贴合物体）不能纯位置控制——硬顶会打坏零件或机器人。阻抗控制和导纳控制都是让机器人表现得像**带弹簧阻尼的质量块**，但实现路径不同。

**阻抗控制**是「给位置偏差，输出力」：F = M_d·ẍ + B_d·ẋ + K_d·(x-x_d)。它要求底层能**直接控制力矩**，协作直驱臂可以，传统工业臂的位置伺服很难做。

**导纳控制**反过来：「测到外力，修正位置目标」。六维力传感器读 F_ext，通过导纳方程积分出位置修正量 Δx_d，叠加到原 x_d 上，再交给内层位置 PID 去跟。工业臂 + 力传感器的主流方案就是这个。

记忆口诀：**阻抗出力，导纳改位置；工业臂常用导纳，协作臂可阻抗。**


|     | 阻抗 Impedance                 | 导纳 Admittance                    |
| --- | ---------------------------- | -------------------------------- |
| 输入  | 位置偏差 x-x_d                   | 力 F_ext                          |
| 输出  | 力 τ                          | 位置修正 Δx_d                        |
| 模型  | F = M_dẍ + B_dẋ + K_d(x-x_d) | M_dẍ = F_ext - B_dẋ - K_d(x-x_d) |
| 硬件  | **力矩控制**                     | **位置伺服 + 力传感器**                  |
| 典型  | 协作直驱臂                        | **工业臂+六维力**                      |


**导纳外环流程：**

```
Step 1  读 F_ext（力传感器）
Step 2  M_d ẍ = F_ext - B_d ẋ - K_d (x-x_d)
Step 3  积分得 Δx_d
Step 4  x_d' = x_d + Δx_d → 内环位置 PID
```

---



### 3.1.4 力位混合（Raibert & Craig）

**口述描述：**

很多任务不是全程力控或全程位控，而是**不同方向不同策略**。比如轴孔装配：XY 方向要对准（位置控），Z 方向要恒力插入（力控）。Raibert & Craig 力位混合用选择矩阵 S 把任务空间拆开：S 对角为 1 的维度走位置控制，为 0 的维度走力控制。

工程上是一个**状态机**：Phase1 全位置接近；Phase2 检测到接触力超过阈值；Phase3 切换到 Z 力控 + XY 位控；Phase4 完成后退回位置控退出。π0.5 折纸 crease 阶段失败，根因就是纯位置 IL 学不到法向力——正是力位混合要解决的问题。

```
S·F + (I-S)·X = 目标
S 对角：1=位置控，0=力控
```

**装配流程：**

```
Phase1 接近：S=I 全位置，笛卡尔直线
Phase2 接触检测：|F_z| > F_thresh
Phase3 插入：S=diag(1,1,0)  Z力控 XY位置
Phase4 完成：S=I 退出
```



### 面试快答

- **CTC 各项含义：** M 惯性前馈、C 离心、G 重力、PD 兜底  
- **工业臂为何导纳：** 内环是位置伺服，难直接力矩控  
- **力位混合 S 矩阵：** 对角划分位置/力子空间

## 3.2 动力学方程与参数辨识



### 口述描述

动力学方程 τ = M(q)q̈ + C(q,q̇)q̇ + G(q) + F(q̇) 描述**「要产生这样的运动，每个关节需要出多少力矩」**。M 是惯性，C 是离心科氏，G 是重力，F 是摩擦。CTC、重力补偿、碰撞检测里的力估计都依赖它。

**参数辨识**解决的是：URDF 里的质量、惯量、摩擦和真机不一致，怎么标定？关键是线性参数化 τ = Y(q,q̇,q̈)·P——力矩对参数线性，P 是组合参数向量。流程是：设计一条**充分激励**的轨迹（傅里叶级数常见），真机跑一遍采集 q、q̇、τ；用 Pinocchio 构造 Regressor Y；堆叠成 τ_stack = Y_stack·P 做最小二乘或岭回归；换一条验证轨迹看 RMSE。真机难点是电流估力矩有摩擦残差、q̈ 数值微分噪声大，要滤波和正则化。

辨识完至少先上 G(q) 或 G+F 前馈，A/B 对比跟踪误差——这是面试可讲的完整闭环。

### 方程

```
τ = M(q)q̈ + C(q,q̇)q̇ + G(q) + F(q̇)
```



### 线性参数化

```
τ = Y(q,q̇,q̈) · P
P：组合参数（base parameters），非单个 m、I 独立可辨识
```



### 完整辨识流程（逐步）

```
Step 1  设计激励轨迹
        - 傅里叶级数 q(t)=Σ(a_k sin(kωt)+b_k cos(kωt))
        - 约束：限位、v/a 上限、persistent excitation
        - 优化：最小化 cond(Y)
Step 2  真机/仿真执行轨迹，采样 q, q̇, τ（或 I→τ）
Step 3  q̈：Savitzky-Golay / Butterworth（噪声敏感）
Step 4  Pinocchio buildRegressor → Y_stack
Step 5  τ_stack = Y_stack · P → LS 或岭回归
Step 6  验证轨迹：RMSE(τ_pred, τ_meas)
Step 7  上线 G 或 G+F 前馈，A/B 对比跟踪误差
```

**优劣：**


| 优点            | 缺点       |
| ------------- | -------- |
| 提高 CTC/重力补偿精度 | 激励设计费时   |
| 可量化 RMSE      | 电流估力矩误差大 |
| 仿真可先行         | 摩擦非线性需分开 |




### 面试快答

- **为何组合参数 P？** 单个物理量不可辨识，线性组合可辨识  
- **激励为何要 PE？** Y 满秩，否则 LS 病态  
- **真机难点：** 摩擦、电流估力矩、q̈ 噪声

## 3.3 摩擦建模与辨识



### 口述描述

摩擦是动力学里最难建模的部分，低速段尤其明显。常见模型是：**库仑摩擦** Fc·sgn(q̇)（换向时跳变）+ **黏性摩擦** Fv·q̇（和速度成正比）+ **Stribeck**（低速时摩擦更大，导致爬行）。

辨识做法相对独立：单关节低速匀速**正转再反转**，记录力矩-速度曲线，会形成一个滞回环——环宽反映库仑摩擦，斜率反映黏性。通常**先标 G(q) 重力，再低速扫摩擦**，否则混在一起分不开。补偿放在前馈 τ_ff += F(q̇)。未补偿时表现为低速爬行、力控「顶不住」、跟踪曲线有滞回。

### 模型

```
F(q̇) = Fc·sgn(q̇) + Fv·q̇ + (Fs-Fc)·exp(-(q̇/vs)²)·sgn(q̇)  // Stribeck
```



### 辨识流程

```
Step 1  单关节低速匀速正反扫
Step 2  记录 τ vs q̇ → 滞回环
Step 3  分离 Fc（换向跳变）、Fv（斜率）
Step 4  与动力学辨识分离：先 G，再低速扫摩擦
Step 5  前馈 τ_ff += F(q̇)
```

**未补偿影响：** 低速爬行、力控顶不住、跟踪滞回。

## 3.4 减速器 · 精度 · 半全闭环



### 口述描述

谐波/RV 减速器是机械臂精度误差的主要来源。**齿隙**是换向时的空程，表现为正转改反转时位置突然跳一下；**传动误差**来自齿形和节距，是周期性的；**弹性变形**是重载下柔轮被压弯，指令到了但末端还没到位；**摩擦滞回**导致低速时不跟手。

**半闭环**指编码器装在电机端：你控的是电机转角，经过减速比 N 推算输出端角度，但减速器内部的齿隙和弹性**不在反馈回路里**，测不到也补不了。**全闭环/双编码器**在输出端再加一个编码器，Δθ = θ_motor/N - θ_out 直接反映传动内部误差，可以做齿隙补偿表——正转反转分开查表补偿。

**重复定位精度**是同样条件重复走多次的一致性；**绝对定位精度**是指令位置和激光跟踪仪实测的偏差，还涉及 DH 标定、温漂等。赛博格面试爱问：怎么测、怎么补、半闭环为什么难补齿隙。

### 误差来源


| 误差   | 机理   | 控制影响       |
| ---- | ---- | ---------- |
| 齿隙   | 换向间隙 | 位置突变、力矩不连续 |
| 传动误差 | 齿形   | 周期性波动      |
| 弹性   | 负载变形 | 重载漂移       |
| 摩擦滞回 | 预紧   | 低速爬行       |




### 半闭环 vs 全闭环

```
半闭环：编码器电机端 → 减速器内误差不可见
全闭环：输出端/双编码器 → 齿隙在反馈内
```

**双编码器：** `Δθ = θ_motor/N - θ_out`

### 齿隙补偿流程

```
Step 1  正反慢扫记录滞回
Step 2  建 comp(θ, direction) 查表
Step 3  θ_cmd = θ_ideal + comp
```



### 绝对 vs 重复定位精度


|      | 定义         | 影响因素        |
| ---- | ---------- | ----------- |
| 重复精度 | 同条件多次回归离散度 | 摩擦、控制       |
| 绝对精度 | 指令位 vs 实测位 | 标定、DH、传动、温漂 |

## 3.5 CANopen / EtherCAT



### 口述描述

分布式关节模组常用 **CANopen** 协议通信。理解它先抓 **NMT 状态机**：上电 Initializing → Pre-operational（可以 SDO 读写参数配置）→ Operational（PDO 周期性收发过程数据，位置/速度/力矩真正跑起来）→ Stopped 急停。

**SDO** 像「读写信」，用来配 PID 增益、限位、模式；**PDO** 像「广播实时数据」，每个周期自动发，延迟低。湃特纳面试原题：SDO 从 Pre-operational 起就能发。EtherCAT 是工业实时以太网，1ms 级周期，PDO 概念类似 CANopen 但带宽更高，高端协作/工业臂驱动常见。

### CANopen NMT 状态

```
Initializing → Pre-operational → Operational
                              ↘ Stopped
```


| 状态          | SDO  | PDO   |
| ----------- | ---- | ----- |
| Pre-op      | ✓ 配置 | ✗     |
| Operational | ✓    | ✓ 周期性 |


**SDO：** 参数读写（Index:Subindex）。**PDO：** 实时位置/速度/力矩。

### EtherCAT（了解）

工业实时以太网，1ms 周期，PDO 概念同 CANopen，带宽更高。

### 面试快答

- **SDO 从哪状态可发？** Pre-operational 起  
- **半闭环齿隙难补原因？** 误差在减速器内，电机端编码器测不到

## 3.6 手眼标定 · 视觉伺服



### 口述描述

视觉抓取要把像素坐标变成机器人能执行的关节角，中间必须经过**手眼标定**。Eye-in-Hand 是相机装在法兰上，Eye-to-Hand 是相机固定在外部。标定方程 AX=XB 的含义是：机器人做几组已知运动 A_i，相机看到标定板相对相机的位姿 B_i，解出 X（相机相对法兰或 base 的固定变换）。

流程：机械臂带标定板动 15–20 组，充分旋转；OpenCV calibrateHandEye 求解；看重投影误差。之后抓取链路是：(u,v,d) 反投影到相机 3D 点 → 乘 T_base^cam 到基座系 → IK 求 q。

**视觉伺服**分 PBVS（3D 位姿误差驱动）和 IBVS（图像特征误差驱动），后者不依赖精确深度模型，实时伺服常用。

### 手眼方程 AX = XB


| 类型          | 相机位置 | X 含义      |
| ----------- | ---- | --------- |
| Eye-in-Hand | 法兰上  | 相机相对法兰    |
| Eye-to-Hand | 外部固定 | 相机相对 base |


**标定流程：**

```
Step 1  机械臂多组运动 (R_i, t_i)，相机见标定板 (A_i, B_i)
Step 2  OpenCV calibrateHandEye / Tsai-Lenz
Step 3  验证：重投影误差 < 1 pixel
```



### 视觉→抓取

```
(u,v,d) → K⁻¹ → P_cam → T_base^cam · P_cam = P_base → IK → q
```



### 视觉伺服


| 类型   | 误差    | 特点      |
| ---- | ----- | ------- |
| PBVS | 3D 位姿 | 需深度     |
| IBVS | 图像特征  | 不标定深度模型 |

## 4.1 VLA 分层控制架构



### 口述描述

VLA 推理慢（几十到上百 ms），但机械臂伺服要快（500Hz–1kHz），**不能等模型每步都算完才动**。分层架构的核心是**把「想做什么」和「怎么平滑执行」拆开**：

上层 VLA 2–10Hz 输出一段 **action chunk**（比如未来 8–50 步的 Δq），相当于「未来一小段时间的方向盘怎么打」；中层 100–500Hz 对 chunk 做样条或线性插值，填出高频 setpoint；底层 500–1000Hz 伺服环做 PID、重力前馈、限位和安全裁剪。

110ms 推理如何实现 50Hz 控制？因为 chunk 一次输出 K 步，执行层在这 K 步内高频插值跟踪，不必每 2ms 都等一次推理。KV cache、FP16、torch.compile 则缩短单次推理时间。Action 用 Δq 还是绝对 q、chunk 多长，是在「平滑/泛化/反应速度」之间的工程 trade-off。

### 三层架构

```
┌─────────────────────────────────┐
│ VLA 2–10 Hz：输出 chunk (K×Δq)  │
└───────────────┬─────────────────┘
                │ 双缓冲/队列
┌───────────────▼─────────────────┐
│ 插值 100–500 Hz：样条/线性       │
└───────────────┬─────────────────┘
                │
┌───────────────▼─────────────────┐
│ 伺服 500–1000 Hz：PID+前馈+安全  │
└─────────────────────────────────┘
```



### 延迟预算（π0.5 示例）


| 环节       | 典型         | 优化                    |
| -------- | ---------- | --------------------- |
| VLA 推理   | 110ms      | KV cache、FP16、compile |
| chunk 掩盖 | K=8~50 步   | replan 周期 > 推理时间      |
| 插值       | <1ms       | 预计算样条                 |
| 端到端      | 目标<100ms感知 | 分层异步                  |




### Action 表示对比


| 表示    | 优    | 劣      |
| ----- | ---- | ------ |
| Δq    | 平滑   | 漂移     |
| 绝对 q  | 无漂移  | 泛化差    |
| 末端 Δx | 任务相关 | +IK 延迟 |
| chunk | 掩延迟  | 环境变过时  |




### 面试快答

- **110ms 推理如何 50Hz 控？** chunk 输出 K 步 + 高频插值执行  
- **分层原因：** 推理慢，执行不能等

## 4.2 插值 vs 拟合 · 样条 · Minimum Jerk



### 口述描述

**插值**要求曲线**严格经过**每个给定点——MoveIt 的 waypoints 到 SDK 执行，必须在 t_i 时刻精确到达 q_i，所以用三次样条等在点与点之间补光滑曲线。**拟合**则是找一条「总体最接近数据」的曲线，允许不过点——示教数据有噪声，用 Savitzky-Golay 或最小二乘拟合降噪，属于离线处理。

浙江滴石面试那题「从起点到终点补中间点成直线算不算插值」——算，是参数化直线插值。Minimum Jerk 轨迹（五次多项式）因为符合人手 reaching 的加加速度特性，抓取接近段常用，看起来比线性插值更自然。

### 本质区别


|     | 插值              | 拟合         |
| --- | --------------- | ---------- |
| 定义  | **严格过**每个点      | 最小化误差，可不过点 |
| 例   | 三次样条过 waypoints | SG 滤波示教数据  |
| 场景  | MoveIt→SDK 实时执行 | 离线降噪       |




### 三次样条流程

```
输入：waypoints (t_i, q_i)
Step 1  每段三次多项式，C² 连续
Step 2  边界：q̇(0), q̇(T) 或 natural
Step 3  500Hz 采样输出
```



### Minimum Jerk

```
x(t) = x0 + (xf-x0)[10τ³ - 15τ⁴ + 6τ⁵],  τ=t/T
```

符合人类 reaching 运动，抓取接近常用。

### SG 滤波（拟合）

滑动窗口内多项式 LS，保边去噪，示教轨迹平滑。

## 4.3 Action Chunk · warm-start 检索



### 口述描述

**Action chunk** 是 VLA 掩盖推理延迟的核心机制：模型不是每步输出一个动作，而是一次输出未来 K 步 [a_t, …, a_{t+K-1}]，执行层按 50Hz 从这段 buffer 里取点执行；到 replan 周期再算下一段。K 越大，对延迟越不敏感，但环境突变时旧 chunk 可能「过时」；K 越小，反应快但容易断档。

**warm-start 检索**是另一条路：当前状态 + 任务描述构成特征，在 demo 库里用 FAISS/KD-tree 找最相似的历史轨迹，直接当初值或局部跟踪，把 OMPL 几百 ms 的规划降到 ms 级。前提是 demo 库覆盖够、检索特征设计合理。浙江滴石/VLA 实时系统都会问到这类「离散 demo 怎么低延迟找路径」。

### Chunk 执行

```
VLA 每 T_replan 输出 [a_t, …, a_{t+K-1}]
执行层 50Hz 从 chunk 插值
replan 时：discard 旧 chunk 或 blend
```

**K 权衡：** K 大→掩延迟但反应慢；K 小→灵敏但易断。

### warm-start 检索流程

```
Step 1  特征 s = [q, q̇, task_embed]
Step 2  FAISS/KD-tree 在 demo 库找 top-K 近邻
Step 3  时间对齐 demo 轨迹
Step 4  作规划初值 / 直接跟踪 / RL warm-start
```

**优势：** 规划 ms→μs 级；**劣势：** 需高质量 demo 库。

## 4.4 VLA 动作安全层



### 口述描述

VLA 输出的是学习到的动作，**没有硬约束保证不碰撞、不超限**。安全层是在模型和真机之间的「保险丝」——我在 π0.5 里的做法是：VLA 输出 Δq 后，先做 joint limit clamp；再调 MoveIt 的 discrete collision check 看从当前 q 到目标 q 会不会自碰或碰环境；如果有风险，把动作 scale 0.5 或直接 reject。这不是 OMPL 全路径规划，而是**单步轻量检测**，延迟可控，物理层兜底模型胡来的动作。

### π0.5 流程

```
VLA 输出 Δq
  ↓ joint limit clamp
  ↓ MoveIt discrete collision check（当前→目标）
  ↓ 若碰撞或超限：scale 0.5 或 reject
  ↓ 下发 SDK
```

**特点：** 规划时碰撞的轻量版；逐步检测，非 OMPL 全路径。

## 4.5 Sim-to-Real 排查框架



### 口述描述

Sim-to-Real 不是「仿真成功率多少」一个数字，而是**按类别系统排查 gap**。我习惯分五类：动力学（摩擦/力模型不对，纸会滑）、感知（外参漂移，抓不准边）、几何（柔性体 sim gap，纸形变）、控制（推理延迟 vs 控制频率）、动作空间（分布外，指节打限位）。

每个问题用同一模板写：**现象 → 根因 → 手段 → before/after 数字**。π0.5 例子：sim 38% 但真机首测 12%，不追求 sim 绝对值，用 sim 做相对排序 + DR，真机靠增采和 SAC 拉 crease；优化后 12%→34%。面试讲 S2R 用这个框架比罗列问题更有资深感。

### 问题分类表


| 类别  | gap  | π0.5 案例       | 手段              |
| --- | ---- | ------------- | --------------- |
| 动力学 | 摩擦/力 | 纸滑动           | 力控、慢速、增采        |
| 感知  | 外参   | 相机漂移          | ArUco online 标定 |
| 几何  | 柔性   | 纸形变           | DR，sim 做相对排序    |
| 控制  | 延迟   | 110ms vs 50Hz | chunk+KV cache  |
| 动作  | OOD  | L6 饱和         | clamp+SAC 惩罚    |


**模板：** 现象 → 根因 → 手段 → before/after 指标（如 12%→34%）

## 4.6 数采：时间同步 · 主从映射 · 动作空间



### 口述描述

数采质量决定 VLA 上限，运控工程师要参与 **action 空间定义和时间对齐**。

**时间同步：** 头摄、腕摄、IMU、关节状态往往各打各的时间戳。粗同步用 NTP（ms 级）；工业/多相机用 PTP IEEE1588（μs 级）；最高用硬件 trigger 同步曝光。后处理可以对齐：选机器人 controller 为主时钟，其他传感器估计 offset，对不上时用线性插值 q(t) 或 slerp 姿态。

**主从映射：** 人/hand 的 pose 要经过尺度缩放、工作空间裁剪、奇异规避，才能映射到从端机器人关节，否则数据不可回放。

**动作空间**必须在采之前就规范：绝对 q 还是 Δq、关节空间还是笛卡尔、50Hz 还是 100Hz、stamp 打 sensor 时间还是 action 时间——这些决定训练能不能收敛、部署能不能复现。诺亦腾/安努/遥操作岗必问。

### 时间同步


| 方法           | 精度  | 场景          |
| ------------ | --- | ----------- |
| NTP          | ms  | 粗           |
| PTP IEEE1588 | μs  | 工业/多相机      |
| 硬件 trigger   | 最高  | 同步曝光        |
| 软件对齐         | —   | 后处理插值/slerp |


**对齐流程：**

```
Step 1  选主时钟（机器人 controller）
Step 2  各传感器 offset 估计
Step 3  非同步流：线性插值 q(t) 或 slerp 姿态
```



### 主从映射

```
主端 pose → 尺度缩放 → 工作空间裁剪 → 奇异规避 → 从端 q
```



### 动作空间定义（数采必规范）


| 决策    | 选项               | 影响    |
| ----- | ---------------- | ----- |
| 绝对/相对 | q vs Δq          | 漂移/泛化 |
| 空间    | 关节 vs 笛卡尔        | IK 依赖 |
| 频率    | 20/50/100 Hz     | 数据量   |
| 时间戳   | sensor vs action | 对齐    |
