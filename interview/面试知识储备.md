## 1. Isaac Sim 仿真场景设计



### 1.1 面试题意

给定 URDF，在 Isaac Sim 中搭建可运行的仿真场景；若 URDF 中**底盘无法运动**，如何设计与处理。

### 1.2 标准搭建流程

```
URDF/SRDF 准备
    ↓
导入 Isaac Sim（URDF Importer / Isaac Utils）
    ↓
物理与关节配置（Articulation、Drive、碰撞体）
    ↓
场景资产（地面、货架、障碍物、物料）
    ↓
传感器（RGB-D、激光雷达、接触力）
    ↓
ROS2 Bridge + ros2_control 插件
    ↓
与上层 MoveIt2 / 状态机 / Agent 联调
```

**逐步说明：**


| 步骤           | 做什么                                         | 注意点                               |
| ------------ | ------------------------------------------- | --------------------------------- |
| URDF 检查      | 连杆、关节限位、惯性、碰撞 mesh                          | 质量/惯量离谱会导致仿真发散                    |
| 导入           | `isaacsim.asset.importer.urdf` 或 GUI Import | 检查关节轴向、父子层级                       |
| Articulation | 设为 Articulation Root                        | 固定基座用 `fix_base=True`             |
| Drive        | 位置/速度/力矩驱动模式                                | 与真实控制器一致                          |
| 碰撞           | 简化 mesh，设摩擦/恢复系数                            | 过细 mesh 拖慢仿真                      |
| ROS2         | `isaac_ros2_bridge`、`ros2_control`          | MoveIt2 走 `FollowJointTrajectory` |




### 1.3 底盘动不了：原因与处理

**常见原因：**

1. URDF 中 `base_link` 与 `world` 为 **fixed joint**，整机关节为 fixed
2. 只有机械臂 URDF，**没有移动底盘关节**（无 `wheel_joint` / `prismatic`）
3. 关节未配置 **Drive API**，有 joint 但无驱动
4. 用了 **Floating Base** 但未给约束，或物理穿透卡死
5. `ros2_control` 的 **controller 未加载**，命令发不出去

**处理策略（按场景选）：**


| 场景        | 方案                                                                   |
| --------- | -------------------------------------------------------------------- |
| 只验证机械臂/码垛 | `fix_base=True`，底盘当静态障碍物，**只规划 arm**                                 |
| 需要 AGV 导航 | 在 URDF 中补全差速/全向轮关节 + `diff_drive_controller`                         |
| 底盘暂不可改    | 用 **JointState 注入** 或 **TF 发布** 模拟底盘位姿，解耦 arm 与 base 测试              |
| 仿真中临时替代   | 将 fixed 改为 **planar / floating**（带阻尼），或加 **Articulation Drive** 到轮关节 |
| Isaac 侧   | 检查 `ArticulationController` 是否绑定到轮关节；GUI 中手动拖动物体看是模型问题还是控制问题         |


**面试回答结构建议：**

> 先确认需求是「只测臂」还是「整机导航」。只测臂则固定基座、补碰撞与传感器即可；要导航则审计 URDF 关节链、补 drive 与 ros2_control，必要时拆分 base 与 arm 的 controller。全程用 `/joint_states` 和 TF 验证哪一级没动起来。



### 1.4 与 MoveIt2 / Isaac ROS 的衔接

- **感知**：深度相机 → `isaac_ros_nvblox`（障碍 voxel）→ MoveIt2 Planning Scene
- **规划**：MoveIt2 + OMPL（CPU）或 `isaac_ros_cumotion`（cuRobo GPU，毫秒→微秒级）
- **执行**：MoveIt2 → `FollowJointTrajectory` Action → Isaac `ros2_control` 插件

## 2. Agent + 仿真 + 状态机 ROS2 架构设计



### 2.1 三层分工

```
┌─────────────────────────────────────────┐
│  Agent 层：任务理解、决策、异常恢复策略   │
└──────────────────┬──────────────────────┘
                   │ 任务目标 / 高层指令
┌──────────────────▼──────────────────────┐
│  状态机层：流程编排、子模块调度、超时重试   │
│  ├── 底盘导航                            │
│  ├── 视觉感知                            │
│  ├── IK / 运动规划                       │
│  └── 末端执行器（吸盘开闭等）              │
└──────────────────┬──────────────────────┘
                   │ Action / Service 调用
┌──────────────────▼──────────────────────┐
│  仿真 / 硬件层：Isaac Sim 或真机          │
└─────────────────────────────────────────┘
```



### 2.2 Topic / Service / Action 选型原则


| 类型          | 适用场景          | 特点           |
| ----------- | ------------- | ------------ |
| **Topic**   | 连续、高频、可丢帧的数据流 | 异步、多订阅者      |
| **Service** | 短请求、需立即返回     | 同步、一对一、不宜长阻塞 |
| **Action**  | 长任务、需进度与可取消   | 目标-反馈-结果、带取消 |




### 2.3 各子模块接口设计示例



#### 底盘导航


| 接口                   | 类型         | 消息/服务                       | 说明            |
| -------------------- | ---------- | --------------------------- | ------------- |
| `/cmd_vel`           | Topic      | `geometry_msgs/Twist`       | 底层速度（仿真/差分驱动） |
| `/odom`              | Topic      | `nav_msgs/Odometry`         | 里程计反馈         |
| `/navigate_to_pose`  | **Action** | `nav2_msgs/NavigateToPose`  | 点到点导航（Nav2）   |
| `/localization_pose` | Topic      | `geometry_msgs/PoseStamped` | 定位结果          |




#### 视觉传感器


| 接口                        | 类型          | 消息                        | 说明          |
| ------------------------- | ----------- | ------------------------- | ----------- |
| `/camera/color/image_raw` | Topic       | `sensor_msgs/Image`       | 彩色图         |
| `/camera/depth/image_raw` | Topic       | `sensor_msgs/Image`       | 深度图         |
| `/camera/depth/points`    | Topic       | `sensor_msgs/PointCloud2` | 点云          |
| `/detect_object`          | **Service** | 自定义 `DetectObject.srv`    | 触发一次检测，返回位姿 |
| `/track_object`           | Topic       | 自定义 `ObjectPoseArray`     | 连续跟踪（码垛场景）  |




#### IK / 运动规划


| 接口                    | 类型      | 消息                                   | 说明           |
| --------------------- | ------- | ------------------------------------ | ------------ |
| `/move_group`         | Action  | `moveit_msgs/MoveGroup`              | MoveIt2 标准接口 |
| `/compute_ik`         | Service | `moveit_msgs/GetPositionIK`          | 单次 IK 求解     |
| `/execute_trajectory` | Action  | `control_msgs/FollowJointTrajectory` | 轨迹执行         |
| `/joint_states`       | Topic   | `sensor_msgs/JointState`             | 全关节状态（必选）    |




#### 末端吸盘


| 接口                 | 类型         | 消息                          | 说明                                   |
| ------------------ | ---------- | --------------------------- | ------------------------------------ |
| `/gripper_command` | **Action** | 自定义 `SuctionControl.action` | 吸取/释放，带真空度反馈                         |
| `/vacuum_pressure` | Topic      | `std_msgs/Float32`          | 真空压力监测                               |
| `/gripper_state`   | Topic      | 自定义 `GripperState`          | `IDLE / GRASPING / SUCCESS / FAILED` |




### 2.4 关键自定义消息结构（示例）

```yaml
# SuctionControl.action
# Goal
bool enable          # true=吸取, false=释放
float32 timeout_sec  # 最大等待时间
---
# Result
bool success
string message
float32 final_pressure
---
# Feedback
float32 current_pressure
uint8  phase         # APPROACHING, SEALING, HOLDING

# ObjectPoseArray.msg（视觉输出）
std_msgs/Header header
geometry_msgs/Pose[] poses
string[] object_ids
float32[] confidences
```



### 2.5 状态机设计要点

**典型码垛状态：**

```
IDLE → NAV_TO_PICK → PERCEIVE → PLAN_PICK → EXEC_PICK
     → NAV_TO_PLACE → PERCEIVE_PLACE → PLAN_PLACE → EXEC_PLACE → IDLE
```

**子状态失败处理：**


| 失败类型      | 检测方式                | 处理策略                     |
| --------- | ------------------- | ------------------------ |
| 导航失败      | Action aborted / 超时 | 重试 N 次 → 换路径点 → 上报 Agent |
| 视觉无目标     | confidence < 阈值     | 调整视角 / 补光 → 重拍 → 人工介入    |
| IK / 规划失败 | MoveIt error code   | 换姿态种子、放宽约束、关节空间绕路        |
| 吸取失败      | 真空度 < 阈值            | 下压再吸 → 换抓取点 → 跳过该箱       |
| 执行中断      | Controller 报错       | 急停 → 保持当前状态 → 安全回撤       |


**异常处理通用模式：**

1. **分层错误码**：硬件层 / 规划层 / 任务层，Agent 只看任务层
2. **超时 watchdog**：每个 Action 设 deadline
3. **幂等与可恢复**：记录断点状态，支持从 `PERCEIVE` 重试而非从头
4. **降级**：仿真用完美感知，真机视觉失败时用示教位

## 3. 关节减速器精度误差



### 3.1 误差来源（面试高频）

减速器（尤其谐波、RV）精度误差主要来自：


| 类别               | 机理          | 表现               |
| ---------------- | ----------- | ---------------- |
| **齿隙（Backlash）** | 齿轮副间隙，换向时空程 | 正反转切换时位置突变、力矩不连续 |
| **传动误差**         | 齿形误差、节距累积误差 | 输出轴角度周期性波动       |
| **弹性变形**         | 柔轮、壳体在负载下变形 | 重载下刚度下降、滞后       |
| **摩擦与滞回**        | 预紧、润滑状态变化   | 低速爬行、力矩波动        |
| **温漂**           | 温升改变间隙与刚度   | 长时间运行后零点漂移       |
| **装配误差**         | 同轴度、轴承间隙    | 偏载、振动            |
| **电机端 vs 输出端**   | 半闭环只测电机侧    | 减速器内部误差不可测       |


**谐波减速器特有：**

- 柔轮径向变形 → 非线性刚度
- 椭圆凸轮安装偏心 → 1 倍频传动误差
- 交叉滚子轴承间隙



### 3.2 对控制的影响

- 轨迹跟踪：末端抖动、超调
- 力控：接触力突变、稳定性下降
- 重载码垛：15–30 kg 负载下弹性变形显著，名义 URDF 参数偏差更大

## 4. 精度误差的测量方法



### 4.1 位置偏差测量


| 方法    | 设备           | 适用            |
| ----- | ------------ | ------------- |
| 绝对角度  | 高精度编码器、圆光栅   | 关节级           |
| 末端位置  | 激光跟踪仪、三坐标机   | 系统级绝对精度       |
| 相对重复性 | 多次同轨迹回归      | 重复定位精度        |
| 双编码器法 | 电机端 + 输出端编码器 | **分离齿隙与传动误差** |


**双编码器原理：**

```
θ_motor：电机侧读数
θ_out：输出侧读数
Δθ = θ_motor / N - θ_out   （N 为减速比）
→ 反映减速器内部变形 + 间隙
```



### 4.2 力矩偏差测量


| 方法      | 说明                    |
| ------- | --------------------- |
| 关节力矩传感器 | 直接测 τ，与模型预测对比         |
| 电机电流估计  | τ ≈ K_t · I，低成本但有摩擦误差 |
| 外力矩观测器  | 基于动力学残差估计外力/力矩误差      |
| 静摩擦测试   | 缓慢正反转动，记录起跳力矩 → 静摩擦   |




### 4.3 系统化测试流程

1. **空载**：测传动误差曲线（慢速匀速，傅里叶分析 1×、N× 谐波）
2. **加载**：不同负载下测刚度与滞后回线
3. **动态**：扫频 / 阶跃，看带宽与共振
4. **温升**：冷机 vs 热机对比零点

**面试话术：**  
「位置偏差用双编码器或激光跟踪仪；力矩偏差用力矩传感器或电流估计加动力学残差；要分开齿隙和弹性，需要正反慢扫看滞回环。」

## 5. URDF 动力学参数与实际偏差



### 5.1 URDF 里有什么

```xml
<link>
  <inertial>
    <mass value="..."/>
    <origin xyz="..." rpy="..."/>      <!-- 质心 -->
    <inertia ixx="..." ixy="..." .../> <!-- 惯量张量 -->
  </inertial>
</link>
<joint>
  <dynamics damping="..." friction="..."/>  <!-- 常线性近似 -->
</joint>
```



### 5.2 实际偏差来源


| 参数   | 偏差原因           | 影响       |
| ---- | -------------- | -------- |
| 质量 m | CAD 估重、未含线缆/夹具 | 重力补偿错    |
| 质心位置 | 装配公差、负载变化      | 力矩计算偏    |
| 惯量 I | 简化几何、密度不准      | 加减速跟踪差   |
| 摩擦   | URDF 线性模型过于粗糙  | 低速段力矩误差大 |
| 刚度   | URDF 假设刚体      | 重载下柔性未建模 |




### 5.3 工程处理

1. **CAD 导出** + 实测关键连杆称重修正
2. **在线负载辨识**：抓取不同重量工件时更新等效参数
3. **仿真**：故意加 ±10–20% 扰动做鲁棒性测试
4. **控制**：用辨识参数做前馈，残差用 PID / 观测器补

## 6. 机械臂动力学参数辨识



### 6.1 动力学方程（标准形式）


\tau = M(q)\ddot{q} + C(q,\dot{q})\dot{q} + G(q) + F(\dot{q})


- M：惯性矩阵  
- C：科氏/离心项  
- G：重力项  
- F：摩擦项



### 6.2 线性参数化（辨识核心）

存在 regressor 矩阵 Y(q,\dot{q},\ddot{q}) 和参数向量 P：


\tau = Y(q,\dot{q},\ddot{q}) \cdot P


P 包含各连杆质量、质心、惯量等**组合参数**（不必单独辨识每个物理量）。

### 6.3 辨识流程

```
设计激励轨迹（persistent excitation）
    ↓
采集 q, q̇, q̈, τ（或电流估计 τ）
    ↓
构造堆叠方程  τ_stack = Y_stack · P
    ↓
最小二乘 / 岭回归 / 带约束优化
    ↓
验证：新轨迹上 τ_pred vs τ_meas
```

**激励轨迹要求：**

- 覆盖工作空间，充分激励各参数
- 满足关节限位、速度加速度约束
- 常用：傅里叶级数轨迹、最小条件数优化



### 6.4 分层辨识


| 层级   | 辨识对象       | 方法           |
| ---- | ---------- | ------------ |
| 连杆参数 | m, mc, I   | 空载激励 + 最小二乘  |
| 负载参数 | 末端质量、质心    | 持不同砝码，秩 1 更新 |
| 摩擦   | Fc, Fv, Fs | 低速正反扫、与动力学分离 |
| 关节增益 | K_t, 传动比   | 静力标定         |




### 6.5 与 Sim / 真机

- **仿真**：参数已知，用于验证辨识算法
- **真机**：电流噪声、摩擦非线性、柔性 → 需滤波 + 正则化

## 7. 摩擦参数建模与辨识



### 7.1 常见模型

**库仑 + 粘性（URDF 默认）：**


\tau_f = F_c \cdot \mathrm{sign}(\dot{q}) + F_v \cdot \dot{q}


**Stribeck 模型（低速更准确）：**


\tau_f = F_c \cdot \mathrm{sign}(\dot{q}) + (F_s - F_c) \cdot e^{-(\dot{q}/v_s)^2} \cdot \mathrm{sign}(\dot{q}) + F_v \cdot \dot{q}


- F_s：静摩擦（突破力）  
- F_c：库仑摩擦  
- v_s：Stribeck 速度



### 7.2 辨识方法

1. **低速匀速正反**：分离 F_c、F_v
2. **静止后缓慢加载**：测 F_s
3. **与动力学联合**：在 regressor 中增加摩擦参数列，整体 LS
4. **参数随温度/磨损漂移**：在线慢更新或查表



### 7.3 对控制的意义

- 前馈摩擦补偿 → 改善低速跟踪、减少力控抖动
- 力位混合控制中，未补偿摩擦会导致「顶不住」或「吸不住」

## 8. 全闭环 / 半闭环（闭角法）版本差异

> 面试中「闭角法」多指**全闭环角度测量**与**半闭环**的对比（电机端编码器 vs 输出端编码器）。



### 8.1 半闭环（电机端）

```
电机编码器 → 控制器认为的位置 = θ_motor / N
                    ↓
              [减速器 + 间隙 + 变形]  ← 不可测
                    ↓
              实际输出轴 θ_out
```

- **优点**：成本低、布线简单  
- **缺点**：齿隙、弹性变形不在反馈回路内，**精度受减速器限制**



### 8.2 全闭环（输出端 / 双编码器）

```
电机编码器 ──┐
             ├→ 融合 / 补偿算法 → 更准的 θ_out
输出端编码器 ─┘
```

- **优点**：直接约束输出轴，**消除大部分传动误差与齿隙影响**  
- **缺点**：第二编码器成本、安装空间、多圈绝对值需求



### 8.3 「版本差异」可能指什么


| 维度  | 差异点                     |
| --- | ----------------------- |
| 硬件  | 单圈 vs 多圈绝对值、分辨率、安装方式    |
| 算法  | 单反馈 vs 双反馈融合、齿隙补偿表      |
| 控制  | 半闭环力矩环 + 全闭环位置环（串级）     |
| 标定  | 是否做**齿隙补偿**、**传动误差补偿表** |


**面试回答：**  
「半闭环只保证电机侧角度，负载侧齿隙和变形是开环的；全闭环在减速器输出再加编码器，可把传动误差压进反馈。版本差异体现在编码器分辨率、是否双反馈融合、以及有没有做齿隙补偿标定。」

## 9. MoveIt2 轨迹规划与开源实现

> 问题清单见 [机械臂运控算法详解 §8](./topics/机械臂运控算法详解.md#八轨迹规划与路径规划)；速查见 [MoveIt速查](./topics/MoveIt速查.md)。

### 9.1 MoveIt2 定位

MoveIt2 ≠ 单纯 API，而是**完整运动规划框架**：

```
你的代码 (Python/C++)
    ↓
MoveIt2
    ├── 机器人模型 (URDF + SRDF)
    ├── Planning Scene（世界状态：机器人 + 障碍）
    ├── 运动学 (KDL / Trac-IK / BioIK)
    ├── 路径规划 (OMPL / CHOMP / STOMP / Pilz)
    ├── 碰撞检测 (FCL / Bullet)
    ├── 轨迹后处理（路径简化 + 时间参数化）
    └── 轨迹执行 (FollowJointTrajectory)
```

**面试一句话：** MoveIt2 = 模型 + 场景 + 规划 + 碰撞 + 后处理 + 执行。

### 9.2 SRDF 如何生成

SRDF（Semantic Robot Description Format）**不能从 URDF 自动完整推导**，通常用 **MoveIt Setup Assistant** 生成：

```bash
ros2 launch moveit_setup_assistant setup_assistant.launch.py
```

| 步骤 | 操作 | 写入 SRDF |
|------|------|-----------|
| Load URDF | 加载 `robot.urdf` | — |
| Self-Collisions | 随机采样姿态，判定永远碰不到的连杆对 | **ACM**（Allowed Collision Matrix） |
| Planning Groups | 选 joint 组成 `arm`、`gripper` | `<group>` |
| Robot Poses | 定义 `home`、`ready` 等命名关节角 | `<group_state>` |
| End Effectors | 末端执行器挂接 link | `<end_effector>` |
| Virtual Joints | 机器人固定 world 或装在 AGV 上 | `<virtual_joint>`（可选） |
| Generate | 导出配置包 | `robot.srdf` + launch/yaml |

**ACM 为什么重要：** URDF 相邻连杆碰撞体常重叠（建模简化），全检会误报。ACM 告诉 MoveIt「这两根连杆碰撞可忽略」。

**SRDF 典型片段：**

```xml
<group name="arm">
  <joint name="joint1"/> ... <joint name="joint7"/>
</group>
<disable_collisions link1="link1" link2="link2" reason="Adjacent"/>
<group_state name="home" group="arm">
  <joint name="joint1" value="0.0"/>
</group_state>
```

### 9.3 配置与运行时架构

**前置：**

- `robot.urdf`：连杆、关节、碰撞 几何、速度/加速度限制  
- `robot.srdf`：Planning Group、ACM、命名姿态、末端执行器

**核心节点：**

- `move_group`：规划中枢，订阅 `/joint_states`，维护 Planning Scene  
- `robot_state_publisher`：发布 TF 树  
- `planning_scene_monitor`（可选）：感知更新障碍、执行中监控

### 9.4 调用方式（Python 简例）

```python
from moveit.planning import MoveItPy

moveit = MoveItPy(node_name="my_planner")
arm = moveit.get_planning_component("arm")

arm.set_goal_state(pose_stamped_msg=target_pose, pose_link="end_effector")
# 或 arm.set_goal_state(configuration_name="home")

plan_result = arm.plan()
if plan_result:
    moveit.execute(plan_result.trajectory, controllers=[])
```

### 9.5 `plan()` 内部完整流程

```
arm.plan()
    ↓
① 组装 MotionPlanRequest（起点、终点、规划组、规划器 ID、约束）
    ↓
② Planning Pipeline 调用规划器插件（默认 OMPL）
    ↓
③ OMPL 在关节空间采样 → 每点/每段回调 MoveIt 碰撞检测
    ↓
④ 得到几何路径（只有关节角，无时间）
    ↓
⑤ 路径简化（shortcut）+ 可选平滑（CHOMP/STOMP）
    ↓
⑥ 时间参数化（IPTP / TOTG）→ 满足速度/加速度限制
    ↓
⑦ 返回 RobotTrajectory（JointTrajectory）
    ↓
execute() → FollowJointTrajectory → ros2_control / 真机驱动
```

**各步细节：**

| 步骤 | 谁做 | 做什么 |
|------|------|--------|
| 起点 | `move_group` | 从 `/joint_states` 读当前关节角作为 start state |
| 笛卡尔目标 | IK 插件 | `set_pose_target()` → IK 解为关节目标（多解，需 seed） |
| OMPL 采样 | OMPL | 在 **JointModelStateSpace** 采样；RRTConnect 双向扩展两棵树 |
| 合法性检查 | MoveIt + FCL | StateValidityChecker：FK → checkCollision |
| 边检测 | MoveIt | 两状态间关节空间线性插值 N 点，逐点碰撞检测（防穿墙） |
| 路径简化 | MoveIt | shortcut：远两点间无碰撞则删中间点 |
| 时间参数化 | MoveIt | IPTP（默认）或 TOTG；输入位置序列 + 关节限速 |
| 执行 | trajectory_execution_manager | 按 controller 配置发 `FollowJointTrajectory` |

### 9.6 OMPL 碰撞检测原理

**关键结论（面试必背）：**

> OMPL **本身不做碰撞检测**；通过 `StateValidityChecker` 回调 MoveIt Planning Scene + FCL。  
> 这是**规划时（planning-time）的几何碰撞检测**，不是执行时的力控/接触检测。

```
OMPL 采样关节角 q
    ↓
MoveIt: robot_state.setJointGroupPositions(q)
    ↓
FK → 各 link 位姿 T_i
    ↓
FCL 宽相位（AABB/BVH）→ 窄相位（GJK+EPA / mesh BVH）
    ↓
自碰撞（减 ACM）+ 环境障碍（CollisionObject / Octomap）
    ↓
返回 collision / free
```

| 维度 | 说明 |
|------|------|
| 检测类型 | 几何穿透/距离，非动力学仿真 |
| 何时检测 | 每个采样 state + 路径插值点，规划一次可能数万次 |
| 规划 vs 执行 | 规划阶段保证路径无碰撞；执行默认信任轨迹，场景变化需 replan |
| 为何慢 | RRTConnect 数千次迭代 × 每边插值 10 点 ≈ 数万次 FCL 查询 |

**Planning Scene 内容：**

```
Planning Scene
├── RobotState（关节角 + FK 后 link 位姿）
├── World（CollisionObject、Octomap、nvblox voxel）
├── ACM（SRDF 自碰撞忽略表）
└── 动态 ACM 更新（抓取时临时允许「手爪-物体」碰撞）
```

**规划时碰撞 vs 实时避障：**

| 概念 | 含义 |
|------|------|
| 规划时碰撞 | OMPL 每采一个点就查；不安全的路径不会被接受 |
| 执行时监控 | scene monitor 订阅传感器；场景变了可 stop 或触发重规划 |
| 反应式避障 | 纯 MoveIt+OMPL 不擅长；需 cuMotion（5–20 ms）或控制层避障 |

### 9.7 规划器选型

| 规划器 | 原理 | 特点 | 场景 |
|--------|------|------|------|
| RRTConnect | 双向 RRT | 默认，快 | 通用 Demo |
| RRT* | 采样 + rewiring | 渐近最优，慢 | 路径质量要求高 |
| PRM | 先建路图再查询 | 重复查询同一环境 | 固定工位 |
| CHOMP | 梯度优化 | 路径平滑 | 重复轨迹、码垛 |
| STOMP | 随机轨迹优化 | 避障 + 平滑 | 复杂约束 |
| Pilz | 工业速度规划 | 节拍严格 | 产线 |

**OMPL vs CHOMP：** 采样法（探索空间）vs 优化法（需初始路径，梯度拉平滑）。

### 9.8 笛卡尔路径

```cpp
std::vector<geometry_msgs::Pose> waypoints;
waypoints.push_back(start_pose);
waypoints.push_back(end_pose);

moveit_msgs::RobotTrajectory trajectory;
double fraction = move_group.computeCartesianPath(
    waypoints, 0.01, 0.0, trajectory);
// fraction < 1.0：未走完，常见原因 IK 失败、奇异、碰撞、步长过大
```

**参数：** `step_size`（笛卡尔插值步长，越小越密）、`jump_threshold`（关节跳变阈值，防 IK 解切换）。

### 9.9 源码研究路径

```
moveit2/moveit_ros/move_group          ← 入口
moveit2/moveit_planners/ompl           ← OMPL 接口、StateValidityChecker
moveit2/moveit_core/planning_scene     ← checkCollision 实现
moveit2/moveit_ros/planning            ← planning pipeline 配置
ompl/src/ompl/geometric/planners       ← RRT 等算法本体
```

**关键类：** `MoveGroupInterface`、`PlanningSceneInterface`、`moveit::core::RobotState`、`MotionPlanRequest/Response`。

### 9.10 Isaac 生态加速

| 组件 | 作用 |
|------|------|
| `isaac_ros_nvblox` | 实时 voxel 障碍图 → Planning Scene |
| `isaac_ros_cumotion` | cuRobo GPU 规划，5–20 ms 级 |
| `ros2_control` (Isaac) | 仿真执行 `FollowJointTrajectory` |

### 9.11 面试快答话术

**MoveIt2 架构？**  
URDF/SRDF 定义模型与规划组；Planning Scene 维护世界；规划器（OMPL）在关节空间采样；每点 FCL 几何碰撞；后处理简化 + 时间参数化；经 FollowJointTrajectory 执行。

**SRDF 怎么来？**  
MoveIt Setup Assistant 加载 URDF → 配置 Planning Group、自碰撞 ACM、命名姿态、末端执行器 → 一键生成。

**OMPL 碰撞怎么做？**  
OMPL 不实现碰撞；回调 MoveIt StateValidityChecker；FK 后 FCL broad/narrow phase；规划时对每个采样点和路径插值点同步检测。

**和实时避障区别？**  
经典 MoveIt 是 plan-then-execute；环境变化靠 scene monitor 触发重规划；毫秒级反应式需 GPU 规划器或控制层避障。

**码垛项目建议：** Demo 用 MoveIt2 + RRTConnect；障碍固定手摆 CollisionObject；取放货笛卡尔 + `computeCartesianPath`；回原点关节空间。

## 10. 运动学、控制层与动力学三层关系



### 10.1 分层架构

```
┌─────────────────────────────────────┐
│ 任务层：目标位姿、力曲线、装配策略      │
└──────────────┬──────────────────────┘
               ↓
┌──────────────────────────────────────┐
│ 运动学层：FK / IK / Jacobian          │
│  关节空间 q ↔ 笛卡尔位姿 x            │
│  速度映射：ẋ = J(q)q̇                  │
└──────────────┬───────────────────────┘
               ↓
┌──────────────────────────────────────┐
│ 控制层：PID / 计算力矩 / 阻抗 / 导纳    │
│  输出：关节力矩 τ 或 位置指令           │
└──────────────┬───────────────────────┘
               ↓
┌──────────────────────────────────────┐
│ 动力学层：M(q)q̈ + C + G + F = τ      │
│  模型前馈 + 参数辨识 + 摩擦补偿        │
└──────────────┬───────────────────────┘
               ↓
          电机 / 减速器 / 连杆
```



### 10.2 各层职责

> FK / IK 详解见 [机械臂运控算法详解 §3–§4](./topics/机械臂运控算法详解.md#三正运动学-fk)。

| 层级  | 输入        | 输出      | 典型算法         |
| --- | --------- | ------- | ------------ |
| 运动学 | 末端目标      | 关节角/速度  | FK 链式变换；IK 解析/数值/优化 |
| 控制  | 轨迹误差      | τ 或 q_d | PID、CTC、阻抗   |
| 动力学 | q, q̇, q̈ | 期望 τ 前馈 | 牛顿-欧拉、拉格朗日   |




### 10.3 计算力矩控制（CTC）


\tau = M(q)\ddot{q}_d + C(q,\dot{q})\dot{q}_d + G(q) + K_p e + K_d \dot{e}


- 动力学做**前馈**，PID 做**反馈**  
- 参数不准时前馈误差由反馈兜底，但重载/高速时压力大



### 10.4 面试串联话术

「运动学解决『去哪、关节角多少』；动力学描述『要多少力矩才能这样动』；控制层把轨迹误差和力控目标合成最终 τ。辨识就是为了提高动力学前馈精度，减速器误差影响的是执行层能否跟上控制指令。」

## 11. 力位混合控制



### 11.1 问题背景

接触任务（装配、打磨、吸取贴合）需要：

- 某些方向**位置控制**（垂直插入）  
- 某些方向**力控制**（贴紧、恒压）



### 11.2 混合控制框架（Raibert & Craig）

选择矩阵 S（位置子空间）、S'（力子空间），S + S' = I：


\begin{cases}
\text{位置回路：} & S \cdot (x_d - x) \rightarrow \text{位置控制器} 
\text{力回路：} & S' \cdot (F_d - F) \rightarrow \text{力控制器}
\end{cases}


最终指令在任务空间合成后，经 Jacobian 转关节空间。

### 11.3 实现要点


| 环节  | 说明                         |
| --- | -------------------------- |
| 力测量 | 六维力矩传感器 / 关节力矩估计           |
| 坐标系 | 力控通常在 **tool frame** 定义    |
| 柔顺  | 纯力控需低刚度 → **阻抗/导纳**更常用     |
| 切换  | 接触前位置 → 接触后力，需 **状态机** 防冲击 |
| 稳定性 | 环境刚度 + 控制器刚度，不当会振荡         |




### 11.4 阻抗控制 vs 导纳控制


|     | 阻抗控制         | 导纳控制           |
| --- | ------------ | -------------- |
| 输入  | 位置偏差         | 外力             |
| 输出  | 力            | 位置修正           |
| 实现  | 力矩级，需良好动力学模型 | 外环位置，易与现成位置环集成 |
| 适用  | 直连力矩控制机器人    | 工业位置伺服 + 力传感器  |


**阻抗模型：**


F = M_d \ddot{x} + B_d \dot{x} + K_d (x - x_d)


调节 K_d, B_d 改变「软硬」。

### 11.5 吸盘场景

1. **接近段**：位置控制，笛卡尔直线
2. **接触段**：法向力控 / 恒真空度，切向小力
3. **保持段**：监测 vacuum pressure，掉压则重试
4. **释放段**：关真空 → 位置抬起

摩擦、齿隙会导致法向力建立延迟，需 **慢速接触 + 力阈值确认**。

### 11.6 面试回答结构

> 力位混合用选择矩阵 S 划分子空间：插入方向位置控，贴紧方向力控。工程上常用导纳控制做外环，内环仍是位置伺服。实现关键是力传感器标定、接触切换状态机、以及对减速器柔性/摩擦的补偿，否则力环容易抖或顶不住。

## 12. 穿戴设备多相机动态标定



### 12.1 面试题意

针对手套、头显等穿戴设备上的**多路摄像头**（头部、髋部、手部），在**人体运动**条件下建立各相机坐标系之间的空间变换关系。与固定基座的机器人手眼标定不同，人体是**非刚性、时变**的参考系。

### 12.2 与机器人标定的核心差异


| 维度    | 机器人本体标定    | 穿戴设备人体标定        |
| ----- | ---------- | --------------- |
| 参考系   | 刚体基座，固定外参  | 身体各部位相对运动、软组织形变 |
| 外参稳定性 | 安装后基本不变    | 穿戴松紧、运动导致外参漂移   |
| 标定时机  | 出厂 / 维护时离线 | 需支持在线重标定或持续估计   |
| 传感器分布 | 集中在末端/基座   | 头、髋、双手，拓扑呈链式    |
| 实时性   | 毫秒级可离线算完   | 数采/遥操作往往要实时融合   |




### 12.3 推荐的两层标定架构（面试讨论方案）

```
┌─────────────────────────────────────────────────────────┐
│  第一层：各相机 → 身体局部坐标系（髋部 / 躯干为锚点）      │
│  方法：固定外参（CAD+精标定） 或 视觉-IMU SLAM             │
└──────────────────────────┬──────────────────────────────┘
                           │ T_hip^head, T_hip^hand ...
┌──────────────────────────▼──────────────────────────────┐
│  第二层：手眼关系 — 以头部相机为基准，求手部相机位姿        │
│  方法：Eye-to-Hand / Eye-in-Hand 手眼标定 + 在线修正      │
└──────────────────────────┬──────────────────────────────┘
                           │
                    统一世界系 / 头部系下的多视角融合
```

**为何选髋部作锚点：** 髋部接近人体质心、相对躯干稳定，适合作为「身体坐标系」原点；头显 SLAM 常输出 head 系，需经躯干模型转到 hip 系。

### 12.4 第一层：相机 ↔ 身体坐标系



#### 方案 A — 固定外参（离线精标定）

适用：相机与支架相对身体位置**可重复**（如硬头戴、腰戴支架）。

1. **CAD 初值**：从头显/手套 CAD 得相机相对支架位姿
2. **标定板标定**：用户穿戴后静止摆拍 Charuco / AprilTag 板，多姿态采集
3. **求解**：每路相机内参 K, dist + 外参 T_{body}^{cam}
4. **验证**：重投影误差 < 0.5 px；不同姿态一致性

局限：运动时支架滑动 → 外参失效，需周期性重标定。

#### 方案 B — SLAM / VIO 建身体系

适用：头显自带 IMU + 相机，手部相机可观测环境或身体标记。


| 设备  | 常见方案                                      |
| --- | ----------------------------------------- |
| 头部  | IMU 融合 VIO（ORB-SLAM3、VINS-Mono）→ 头部在世界系位姿 |
| 髋部  | 腰戴 IMU 积分 + 头-髋运动学约束；或外置固定相机看髋部标记         |
| 手部  | 手套相机看桌面特征 / 手臂 ArUco / 与头显双目三角化           |


**头-髋约束（简化运动学）：**

```
T_world^hip ≈ T_world^head · T_head^neck · T_neck^torso · T_torso^hip
```

颈、躯干关节角可由 IMU 或视觉骨架估计，将头显 SLAM 轨迹映射到髋部系。

### 12.5 第二层：手眼标定（以头部为基准）

目标：求 T_{head}^{hand}，使手部相机观测可变换到头部相机坐标系。

**手眼方程（Eye-to-Hand 变体）：**


A X = X B


- A：头部相机相邻帧相对运动 \Delta T_{head}  
- B：手部相机相邻帧相对运动 \Delta T_{hand}  
- X = T_{head}^{hand}（待求外参）

采集要求：手部与头部**独立做充分旋转**（各轴 > 30°），至少 15–20 组运动对；用 Tsai-Lenz / Park-Martin / AX=XB 对偶四元数求解。

**动态场景增强：**


| 手段               | 作用                                |
| ---------------- | --------------------------------- |
| 共视 ArUco / 人体骨架点 | 头手同时观测同一 3D 点，直接三角化约束             |
| 在线外参估计           | EKF / 因子图，将 T_{head}^{hand} 作慢变状态 |
| 穿戴松紧检测           | 重投影误差突增 → 触发重标定                   |




### 12.6 完整标定流程设计（可落地的工程方案）

```
阶段 0：单相机内参标定（产线或实验室，棋盘格）
    ↓
阶段 1：用户穿戴 → 静止多姿态外参标定（头/髋/手 → body）
    ↓
阶段 2：动态手眼标定（头-手相对运动，解 AX=XB）
    ↓
阶段 3：运行时
    ├── 头显 SLAM 提供 T_world^head
    ├── IMU/运动学提供 T_head^hip
    ├── 在线维护 T_head^hand（低通 + 异常检测）
    └── 输出：所有相机统一到 head 或 hip 系
    ↓
阶段 4：质量监控
    └── 重投影误差、共视深度一致性、时间戳对齐检查
```



### 12.7 面试回答话术

> 我会把问题拆成两层：先用固定外参或 SLAM 把各相机挂到身体坐标系（髋部作锚）；再以头部为基准做手眼标定，求手部相对头部的刚体变换。人体是动态参考系，所以外参不能一次标定管终身，需要共视标记或骨架点做在线修正，穿戴松动时靠重投影误差触发重标定。和机器人比，难点在非刚性、外参时变和实时性，不是单次 AX=XB 精度本身。

## 13. 多设备时间戳同步



### 13.1 面试题意

数采设备中头部、手部等多路传感器**时间戳不一致**，如何在采集、回放、训练时保证多模态数据对齐。

### 13.2 不同步的来源


| 层级    | 原因                                       |
| ----- | ---------------------------------------- |
| 硬件时钟  | 各设备独立晶振，存在 ppm 级漂移                       |
| 传输链路  | USB / WiFi / 蓝牙 缓冲延迟不等                   |
| 软件栈   | 驱动回调、OS 调度、不同进程取戳点不一致                    |
| 传感器特性 | 相机 rolling shutter、IMU 1 kHz vs 相机 30 Hz |
| 无硬件触发 | 各设备自由运行，仅软件打戳                            |


```
真实事件发生时刻 t*
    相机 A 记为 t_A = t* + δ_A
    相机 B 记为 t_B = t* + δ_B + jitter
    IMU   记为 t_I = t* + δ_I
→ 不对齐时融合/hand-eye 会引入运动畸变
```



### 13.3 同步策略分层

```
        ┌─────────────────────────────────┐
        │  L1 硬件同步（最优）              │
        │  同一时钟源 / 触发线 / PTP       │
        └───────────────┬─────────────────┘
                        ↓ 做不到时
        ┌───────────────▼─────────────────┐
        │  L2 时钟对齐（软件）              │
        │  NTP / PTP / 主从时钟偏移估计     │
        └───────────────┬─────────────────┘
                        ↓
        ┌───────────────▼─────────────────┐
        │  L3 数据层对齐（必做）            │
        │  时间戳映射 + 插值 / 最近邻       │
        └───────────────┬─────────────────┘
                        ↓
        ┌───────────────▼─────────────────┐
        │  L4 内容对齐（兜底）              │
        │  视觉特征 / IMU 互相关估延迟      │
        └─────────────────────────────────┘
```



### 13.4 L1 — 硬件同步方案


| 方案              | 做法                               | 适用           |
| --------------- | -------------------------------- | ------------ |
| 外部触发            | 同一 GPIO 触发多相机曝光                  | 工业相机、定制板     |
| 共享时钟            | 所有传感器接入同一 MCU/FPGA 打统一戳          | 手套 + 腰盒集中采集  |
| PTP (IEEE 1588) | 以太网设备时钟同步，亚毫秒级                   | 网络化相机        |
| USB 集中采集        | 单主机多路，用 arrival time + 标定 offset | 头显 + USB 手相机 |


头戴 + 无线手相机往往**无法硬触发**，需 L2–L4 组合。

### 13.5 L2 — 时钟偏移估计

**启动时同步脉冲：** 所有设备同时看 LED 闪光 / 拍手，检测信号上升沿，估计 \Delta t_{A,B}。

**周期性互相关（运行时）：**

- IMU 角速度模长 vs 相机光流幅值  
- 两路音频 / 震动传感器互相关  
- 同一 ArUco 在头手相机出现的帧匹配

估计常数偏移 \Delta t 和漂移率 \alpha：


t_B' = \alpha \cdot t_B + \Delta t


用 RANSAC 拟合，抵抗离群帧。

### 13.6 L3 — 数据层对齐（工程最常做）

**统一时间基准：** 选定 master（通常头显主相机或采集主机 `rosbag` 时间）。

**对齐策略：**


| 方法              | 说明                                        | 适用                |
| --------------- | ----------------------------------------- | ----------------- |
| 最近邻             | 找与 master 时间差最小的样本                        | 低动态、高帧率           |
| 线性插值            | 位姿/IMU 在 t_0, t_1 间插值                     | 关节角、SE(3) 用 slerp |
| 窗口聚合            | [t−Δ, t+Δ] 内多帧融合                          | 手相机低帧率            |
| message_filters | ROS2 `ApproximateTime` / `ExactTime` sync | 多 Topic 订阅        |


**ROS2 示例思路：**

```python
# ApproximateTime 同步头、手相机（允许 slop，如 10ms）
sync = ApproximateTimeSynchronizer(
    [head_sub, hand_sub], queue_size=10, slop=0.01)
```

**录制规范：**

- 所有消息用 `header.stamp`（设备时间）+ `recording_time`（主机时间）双戳  
- 录制前做 clock offset 标定写入 metadata  
- bag 回放时用 `static_tf` + 时间偏移 yaml



### 13.7 动态人体场景的额外注意

1. **Rolling shutter**：手快速挥动时，一行曝光时间不同 → 需 RS 校正或提高快门速度
2. **高动态运动**：最近邻误差大 → 必须插值位姿，不能只对图像对齐
3. **无线抖动**：手相机 WiFi 延迟方差大 → 缓冲队列 + 时间戳在**采集端**打上，非接收端
4. **端到端训练**：VLA 可学一定偏移，但 >30–50 ms 会明显损精度，同步仍要做



### 13.8 面试回答话术

> 分四层做：能硬件触发或 PTP 最好；否则启动时闪光估时钟偏移，运行中用 IMU-视觉互相关慢更新。数据层以头显为主时钟，手、髋用最近邻或位姿插值对齐，ROS 用 ApproximateTimeSynchronizer。无线手相机一定要在设备端打戳再传，避免接收端延迟污染。动态人体要额外处理 rolling shutter 和快速运动下的插值，不能只对齐图像不对齐位姿。

## 14. 模型加速、部署与量化



### 14.1 面试题意

模型从训练到端侧/工控机部署的加速流程；**量化**提升推理速度时，如何控制精度损失。

### 14.2 部署全流程

```
训练 (PyTorch/JAX)
    ↓ 导出
ONNX / TorchScript
    ↓ 图优化
算子融合、常量折叠、子图切分
    ↓ 后端编译
TensorRT / ONNX Runtime / OpenVINO / NCNN / RKNN
    ↓ 量化（可选）
FP16 / INT8 PTQ / INT8 QAT
    ↓ 集成
C++ / Python 推理服务、ROS2 node、边缘盒子
    ↓ 验证
精度 benchmark + 延迟 profiling + 真机回归
```



### 14.3 常见加速手段


| 手段          | 原理                 | 典型收益               |
| ----------- | ------------------ | ------------------ |
| FP16 / BF16 | 半精度计算              | 2× 吞吐，精度几乎无损       |
| INT8 量化     | 8 bit 权重/激活        | 2–4×，内存减半          |
| TensorRT    | kernel 融合、层融合、自动调优 | GPU 上 2–10×        |
| 算子融合        | Conv+BN+ReLU 合一    | 减 launch 开销        |
| 剪枝          | 去掉不重要的权重/通道        | 模型变小，需微调           |
| 蒸馏          | 小模型学大模型            | 精度恢复               |
| 动态/静态 shape | 固定输入尺寸利于编译         | TRT 必须常形状或 profile |
| 批处理 vs 单帧   | 吞吐 vs 延迟权衡         | 机器人控制要盯 p99 延迟     |




### 14.4 量化基础

**两种主流量化方式：**


| 类型              | 流程                           | 优点     | 缺点        |
| --------------- | ---------------------------- | ------ | --------- |
| **PTQ**（训练后量化）  | 训练好的 FP32 模型 + 校准集 → 估 scale | 快，无需重训 | 敏感层可能掉点   |
| **QAT**（量化感知训练） | 训练时模拟 INT8 舍入                | 精度最好   | 成本高，要训练资源 |


**量化公式（对称 per-channel 为例）：**


x_{int8} = \mathrm{clip}\left(\mathrm{round}\left(\frac{x}{s}\right), -128, 127\right)


s 由校准集上的 min/max 或 KL 散度最优确定。

### 14.5 如何保证量化后精度不掉太多（核心）



#### ① 校准集要「像真机」

- 用**真实场景**图像/点云，覆盖光照、距离、遮挡  
- 数量通常 200–1000 张即可，关键是分布覆盖  
- 避免只用训练集子集（易过拟合校准统计量）



#### ② 敏感层保留 FP16

- 首层、末层、**小 channel 的层**、Detection head、Depth head 常对量化敏感  
- TensorRT：`precision_constraints`、per-layer FP16  
- 混合精度：骨干 INT8 + 头 FP16



#### ③ 选 per-channel 权重量化

- per-tensor 对大模型往往掉点明显  
- Conv 权重量 per-channel 几乎不增加推理成本



#### ④ PTQ 不够就上 QAT

- 掉点 > 1–2% mAP / 关键指标不达标 → QAT 2–10 epoch 微调  
- 使用 PyTorch `torch.ao.quantization`、NVIDIA QAT Toolkit



#### ⑤ 蒸馏辅助

- FP32 teacher → INT8 student，在 logits 或中间特征上加 KL loss



#### ⑥ 算子与导出注意

- 避免不支持 INT8 的算子（某些 custom op、Resize 模式）导致回退 FP32 或报错  
- ONNX 导出时 `opset`、动态轴要与 TRT profile 一致  
- 量化前后用**同一 benchmark** 对比：mAP、深度 RMSE、关键点误差、端到端任务成功率



#### ⑦ 机器人/视觉任务的特殊指标


| 任务     | 除模型指标外还要看                       |
| ------ | ------------------------------- |
| 目标检测   | 小目标 recall、边界框 IoU              |
| 深度估计   | 绝对深度误差 at 1.25                  |
| 姿态/抓取  | 物理一致性、成功率                       |
| VLA 策略 | 仿真/真机 success rate，不只看 val loss |




### 14.6 TensorRT 部署示例流程

```
1. torch → ONNX (opset 17, simplify onnx)
2. trtexec --onnx=model.onnx --saveEngine=model.plan \
     --fp16                          # 先 FP16 摸底
3. trtexec ... --int8 --calib=calib_cache \
     --calibData=calib_images/        # INT8 PTQ
4. 对比 FP32 / FP16 / INT8 在 val set 上的指标
5. 不达标 → 标记敏感层 FP16 或转 QAT
6. C++ TensorRT runtime + CUDA stream 测 p50/p99 延迟
```



### 14.7 精度-速度权衡决策树

```
FP16 是否满足延迟要求？
├── 是 → 部署 FP16（首选，省心）
└── 否 → INT8 PTQ
         ├── 精度达标 → 部署 INT8
         └── 掉点明显
              ├── 混合精度（部分层 FP16）
              ├── 换 per-channel + 更好校准集
              └── QAT / 蒸馏后再 PTQ
```



### 14.8 面试回答话术

> 部署链路是 PyTorch → ONNX → TensorRT，先 FP16 看延迟够不够；不够再上 INT8 PTQ，用真实场景校准集估 scale，首层末层和 detection head 保留 FP16。量化后用同一套 val 和端到端任务指标对比 FP32，掉点超阈值就做 QAT 或蒸馏。机器人场景不能只看 mAP，要看抓取成功率或深度误差。最后 profiling 看 p99 延迟而不只是平均 FPS。

## 15. 轨迹插值、拟合与实时检索

> 浙江滴石 · 精简速答



### 15.1 插值 vs 拟合 — 本质区别


|      | **插值（Interpolation）**     | **拟合（Fitting）**      |
| ---- | ------------------------- | -------------------- |
| 目标   | 已知起终点/控制点，**补中间点**        | 从带噪采样点**反推**曲线       |
| 是否过点 | 通常**严格过**控制点              | 一般**不过**每点，最小化误差     |
| 典型场景 | 实时轨迹执行、MoveIt 笛卡尔直线       | 示教数据降噪、离线轨迹优化        |
| 例子   | 线性/LERP、三次样条、minimum jerk | 最小二乘多项式、B 样条拟合、SG 滤波 |


**一句话：** 插值是「已知路径形状，生成连续轨迹」；拟合是「从离散实测还原光滑轨迹」。

**直线插值理解：** 从 A 到 B 按时间/弧长均匀补点 → 轨迹连贯，但是**参数化**的直线（关节空间或笛卡尔空间），不等于「拟合出来的最优曲线」。

### 15.2 为什么实际轨迹都是离散点？

- 控制周期固定（如 1 ms / 4 ms），控制器只能收 **q[k]**
- 传感器采样率有限（相机 30 Hz，编码器 1 kHz）
- 存储与通信按帧/按点打包
- 电机驱动器内部也是离散 setpoint 序列

物理运动连续，**数字系统必然离散**；中间光滑性靠插值/拟合重建。

### 15.3 离散 → 平滑曲线：常见方法


| 方法                 | 优点         | 缺点     | 适用        |
| ------------------ | ---------- | ------ | --------- |
| **三次样条**           | C² 连续，过控制点 | 需解三对角阵 | 关节轨迹、离线规划 |
| **B 样条**           | 局部可控、凸包性   | 参数化复杂  | 复杂路径、CAD  |
| **Minimum Jerk**   | 符合人类运动学    | 需边界条件  | 抓取接近段     |
| **多项式最小二乘**        | 实现简单       | 高阶振荡   | 粗平滑       |
| **Savitzky-Golay** | 保峰值、在线可用   | 需选窗口   | 实时滤波      |
| **高斯过程 GP**        | 不确定性估计     | 计算贵    | 小数据、仿真    |




### 15.4 实时系统：从离散数据快速找轨迹

**思路分层：**

```
离线：数据集建索引（KD-tree / FAISS 按起始状态或图像 embedding）
    ↓
在线：当前状态 → 检索 Top-K 相似 demo → 作 warm-start
    ↓
局部：样条插值 / 时间缩放（DTW 对齐）→ 可执行轨迹
    ↓
兜底：RRT / 优化器以检索结果为初值，限时迭代（anytime planning）
```

**工程提速：** 预计算 motion primitives；GPU 加速 embedding 检索；Action chunking；VLA 低频 + 底层 1 kHz 插值跟踪。

### 15.5 VLA 预训练 + 实时推理协同


| 方案                  | 做法                                            | 延迟    |
| ------------------- | --------------------------------------------- | ----- |
| **分层异步**            | VLA 2–10 Hz 出 subgoal；底层 PD/轨迹跟踪 500 Hz–1 kHz | 低     |
| **Action Chunking** | 一次预测 H 步，执行 k 步后 replan                       | 中     |
| **模型压缩**            | FP16/INT8、蒸馏小策略网                              | 降推理耗时 |
| **Speculative**     | 小模型先出动作，大模型异步校正                               | 隐藏延迟  |
| **缓存/模板**           | 相似场景检索 demo 轨迹，VLA 只做分类                       | 最低    |


**原则：** 大模型管「做什么」，小环管「怎么快」；绝不每 1 ms 跑一遍 VLA。

### 15.6 权重设计与均值窗口


\hat{x}*t = \frac{\sum*{i=0}^{N-1} w_i \cdot x_{t-i}}{\sum w_i}



| 权重类型 | 特点     | 用途     |
| ---- | ------ | ------ |
| 等权   | 简单     | 基础平滑   |
| EMA  | 近期权重大  | 在线、低延迟 |
| 高斯   | 中心大边缘小 | 保形平滑   |
| 按置信度 | 好帧权重大  | 多传感器融合 |


**窗口 N：** N 越大越平滑但滞后越大（≈ N/2 采样周期）。控制环 3–7 点，示教 5–15 点；硬约束是可接受滞后（如 < 20 ms）。

### 15.7 面试 30 秒话术

> 插值补中间点让轨迹可执行，拟合从 noisy 离散点还原光滑曲线。实时用 demo 检索 warm-start + 样条，VLA 低频出 chunk、底层高频跟踪。权重 EMA 或高斯，窗口按延迟和噪声折中。

## 16. C++ 面向对象与机器人基础

> 美丽魔方 · 精简速答



### 16.1 封装、继承、多态


| 概念     | 核心                      | 机器人例子                                 |
| ------ | ----------------------- | ------------------------------------- |
| **封装** | 隐藏实现，只暴露接口              | `RobotArm::moveTo()` 不暴露 UDP          |
| **继承** | 子类复用父类，is-a             | `SevenDofArm : public RobotArm`       |
| **多态** | 同接口不同实现，`virtual` 运行时绑定 | `Controller* c = new ImpedanceCtrl()` |


**记忆：** 封装「藏」、继承「扩」、多态「换」。

### 16.2 欧拉角 vs 四元数


|      | **欧拉角 RPY**           | **四元数**                                                |
| ---- | --------------------- | ------------------------------------------------------ |
| 表示   | 3 角（Roll, Pitch, Yaw） | 4 元 (w, x, y, z)，单位长度，数学表示为 $q = [w, x, y, z]$，$|q|=1$ |
| 优点   | 直观、易理解                | 完全避免万向节锁，能平滑插值（slerp），高效复合运算，数值稳定                      |
| 缺点   | 容易出现万向节锁，插值效果差        | 抽象、不直观、计算需归一化，调试不便                                     |
| 物理意义 | 三次转动的分解顺序（如ZYX）       | 用四维向量表达三维旋转，类似旋转轴-角的压缩表达，本质是 $S^3$ 球面上的点               |
| 用法   | 示教、UI显示/人机交互          | 内部姿态存储、SLAM、机器人控制、3D 动画引擎                              |
| 典型操作 | 转欧拉角易理解               | 复合旋转直接四元数相乘，插值用球面线性插值（slerp）                           |
| 小结   | 角度直觉但有陷阱              | 姿态表达的工程“黄金标准”                                          |




### 16.3 LoRA 微调数学原理


W' = W + BA,\quad B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k},\ r \ll \min(d,k)


- W 冻结，只训 A、B；前向 h = Wx + B(Ax)
- 参数量 r(d+k) vs 全量 dk；微调变化往往低秩
- 推理可合并 W' = W + BA 无额外开销



### 16.4 视觉 → 末端点位

```
像素(u,v) + 深度 d → K⁻¹ 反投影 → P_cam
→ T_base^cam（手眼标定）→ P_base → IK → q
```


| 路径      | 场景        |
| ------- | --------- |
| 2D+深度   | 眼在手外、有深度图 |
| 6D 位姿估计 | 抓取、码垛     |


关键：手眼外参 + 去畸变；精度取决于标定和深度质量。

### 16.5 面试 30 秒话术

> 封装藏实现，继承扩代码，virtual 多态换行为。姿态用四元数存储插值，欧拉角只做显示。LoRA 是 W'=W+BA 低秩微调。视觉：像素深度→3D→外参→基座系→IK。
